Content Area 5: Business Context

5.1 Business Types & Models

Sole Trader

One person owns and runs the business

Pros: Easy to set up, full control

Cons: Unlimited liability, limited capital

Partnership

2-20 people share ownership

Pros: Shared responsibility, more capital

Cons: Shared profits, joint liability

Private Limited (Ltd)

Owned by shareholders, separate legal entity

Pros: Limited liability, more capital

Cons: More regulations, shares not publicly traded

Public Limited (PLC)

Shares traded on stock exchange

Pros: Raise large capital, limited liability

Cons: Complex regulations, risk of takeover

  • Efficiency: Automation reduces manual work and errors

  • Customer Reach: Online presence expands market
  • Data-Driven Decisions: Analytics improve decision making
  • Competitive Advantage: Innovation keeps ahead of rivals

5.3 Changeover Methods

Method Description Advantages Disadvantages Best For
Direct Old system stops, new system starts immediately • Fast implementation
• Low cost
• Immediate benefits 		• High risk
• No fallback
• Staff need quick training 		Simple systems, paper-based to digital
Parallel Both systems run simultaneously for a period • Low risk
• Can compare outputs
• Easy fallback 		• High cost
• Double workload
• Slow transition 		Critical systems (payroll, banking)
Pilot Trial with a small group before full rollout • Test before full deployment
• Identify issues early
• Gradual learning 		• Time consuming
• Pilot group may not represent all users
• Doesn't test full load 		Large organizations, multi-site deployments
Phased System introduced in stages/modules • Manageable chunks
• Fix issues per phase
• Gradual learning 		• Longest implementation
• Systems may not integrate well initially
• Complex planning 		Complex systems with modules

Exam Tip: Choosing a Method

Consider:

  • Risk tolerance: How much downtime can be tolerated?
  • Cost: What's the budget?
  • Complexity: How complex is the new system?
  • Training needs: How quickly can users learn?
  • Current system: What are you migrating from?

5.4 Risks in Business Context

Types of Business Risks

Strategic Risks

Poor business decisions, market changes, competition

Example: Choosing wrong technology platform

Operational Risks

Day-to-day business failures, system downtime

Example: Server crashes, power failures

Financial Risks

Budget overruns, currency fluctuations, cash flow

Example: Project costs exceed budget

Compliance Risks

Legal violations, regulatory failures

Example: GDPR breaches, data protection failures

Risk Management Process

  1. Identify: What could go wrong?
  2. Assess: How likely? How severe?
  3. Mitigate: How can we reduce the risk?
  4. Monitor: Track risks continuously
  5. Review: Update risk assessments regularly

Risk Mitigation Strategies

  • Avoidance: Don't do the risky activity
  • Reduction: Take steps to minimize impact
  • Transfer: Insurance, outsourcing
  • Acceptance: Accept the risk and plan for consequences

System Performance Analysis

Metrics to Analyze:

  • CPU Usage: Is processing power maxed out?
  • Memory Utilization: Is RAM being exhausted?
  • Network Bandwidth: Is network capacity sufficient?
  • Throughput: How much data processed per second?

Pattern Analysis & Targeted Marketing

Example: Supermarket finds 60% of nappy buyers also buy baby food

Uses:

  • Cross-Selling: Offer discounts on baby food when nappies are scanned

Benefits of Targeted Marketing:

  • Cost-effective (no wasted marketing)
  • Higher conversion rates (relevant offers)

7.3 Network Protocols & Models

OSI Model (7 Layers)

Layer Name Function Examples
7 Application User interfaces, network services HTTP, FTP, SMTP, DNS
6 Presentation Data formatting, encryption SSL/TLS, JPEG, MPEG
5 Session Manages connections NetBIOS, RPC
4 Transport Reliable data transfer TCP, UDP
3 Network Routing, IP addressing IP, ICMP, routers
2 Data Link MAC addressing, error detection Ethernet, switches
1 Physical Physical transmission Cables, hubs, signals

TCP/IP Model (4 Layers)

  1. Application Layer: HTTP, FTP, SMTP (OSI 5-7)
  2. Transport Layer: TCP, UDP (OSI 4)
  3. Internet Layer: IP, ICMP (OSI 3)
  4. Network Access Layer: Ethernet, Wi-Fi (OSI 1-2)

Key Protocols

  • HTTP/HTTPS: Web browsing (port 80/443)
  • FTP: File transfer (port 21)
  • SMTP: Sending email (port 25)
  • POP3/IMAP: Receiving email (ports 110/143)
  • DNS: Domain name resolution (port 53)
  • DHCP: Automatic IP assignment

7.3 Network Performance

Key Concepts

Bandwidth

The maximum amount of data that can be transmitted over a network in a given time

Measured in: bits per second (bps), Mbps, Gbps

Analogy: Width of a highway - more lanes = more cars can travel

Latency

The delay before data transfer begins

Measured in: milliseconds (ms)

Analogy: Time taken for a car to start its journey

Throughput

The actual amount of data transmitted successfully

Note: Always ≤ Bandwidth (real-world conditions affect it)

Analogy: Actual number of cars that complete the journey

Factors Affecting Throughput

  • Connection Quality: Latency, packet loss, jitter
  • Network Congestion: More users = slower speeds
  • Network Type: Fiber vs. copper vs. wireless
  • Access Point Configuration: Device limits, range, coverage
  • Interference: Physical obstacles, electromagnetic interference

Compression

Lossy Compression

Removes some data permanently

Pros: Smaller file sizes

Cons: Quality loss

Examples: JPEG, MP3, MP4

Lossless Compression

No data lost, can be fully restored

Pros: Perfect quality

Cons: Larger files than lossy

Examples: PNG, ZIP, FLAC

Exam Scenario Example

Video streaming platform has buffering issues:

  • Improve Latency: Reduces delay, stops buffering at start
  • Increase Bandwidth: Allows more data transmission, better quality
  • Best Solution: Address BOTH - latency for responsiveness, bandwidth for quality

7.4 Virtual Environments & 7.5 Cloud Computing

Virtual Machines (VMs)

A software-based computer that runs on a physical machine (host)

Types of Hypervisors

Type 1 (Bare Metal)

Runs directly on hardware

Examples: VMware ESXi, Microsoft Hyper-V

Use: Data centers, enterprise

Type 2 (Hosted)

Runs on top of an OS

Examples: VirtualBox, VMware Workstation

Use: Development, testing, personal use

Benefits of VMs

  • Resource Efficiency: Multiple VMs on one physical machine
  • Isolation: VMs are independent, failures don't affect others
  • Snapshots: Save VM state, easy rollback
  • Testing: Safe environment to test software
  • Cost Savings: Reduce hardware costs

7.3 Network Topologies & Client-Server Models

Common Network Topologies

Topology Description Advantages Disadvantages
Bus All devices on a single cable Simple, cheap, easy to extend Cable failure breaks network, slow with many devices
Star All devices connect to central hub/switch Easy to add devices, one failure doesn't affect others Central device failure breaks network, more cabling
Ring Devices in a circular loop Equal access, no collisions One failure breaks network, hard to troubleshoot
Mesh Each device connects to multiple others Highly reliable, multiple paths Expensive, complex setup and management

Client-Server Model

Client: Device that requests services (your computer, phone)

Server: Powerful computer that provides services (web server, database server)

Advantages

  • Centralized Management: Easier to manage, backup, update
  • Security: Centralized security policies
  • Scalability: Easy to add more clients
  • Resource Sharing: Shared files, printers, applications

Disadvantages

  • Cost: Expensive server hardware
  • Single Point of Failure: If server fails, network down
  • Maintenance: Requires IT expertise
  • Network Dependency: Clients need network connection

7.6 Resilient Environments

7.6.1 Benefits of Resilient Environments

  • High Availability: Systems accessible 24/7/365
  • Business Continuity: Operations continue during failures
  • Data Protection: Prevent data loss
  • Customer Trust: Reliable services build confidence
  • Reduced Downtime Costs: Minimize lost revenue

7.6.2 Methods to Improve Resilience

Redundancy

Duplicate critical components

  • Dual power supplies
  • Multiple NICs (network cards)
  • RAID arrays for storage
  • Backup servers

Failover Systems

Automatic switch to backup when primary fails

  • Hot standby (instant)
  • Warm standby (minutes)
  • Cold standby (hours)

Load Balancing

Distribute traffic across multiple servers

  • Prevents overload
  • Improves performance
  • Provides redundancy

Disaster Recovery

Plans and procedures for major failures

  • Offsite backups
  • Recovery Point Objective (RPO)
  • Recovery Time Objective (RTO)

3-2-1 Backup Rule

  • 3 Copies: Original + 2 backups
  • 2 Different Media: Hard drive + cloud/external drive
  • 1 Offsite: Cloud storage or physical offsite location

Protects against: Hardware failure, theft, fire, natural disasters

RAID Arrays

  • RAID 0: Striping - fast but no redundancy
  • RAID 1: Mirroring - duplicate data on 2 drives
  • RAID 5: Striping with parity - good balance
  • RAID 10: Mirroring + Striping - best performance and redundancy

Content Area 8: Security - CIA Triad

The CIA Triad

The three pillars of information security

Confidentiality

Information is accessible only to authorized users

Threats: Unauthorized access, data breaches, eavesdropping

Integrity

Information remains accurate and unaltered

Threats: Data corruption, unauthorized modifications, malware

Availability

Information is accessible when needed

Threats: DDoS attacks, hardware failures, natural disasters

Protecting Confidentiality

  • Encryption: Scramble data so only authorized users can read it
  • Access Controls: Permissions, authentication, authorization
  • Data Classification: Public, Internal, Confidential, Secret
  • Physical Security: Locks, CCTV, secure locations

Protecting Integrity

  • Data Validation: Check input is correct format
  • Checksums/Hashes: Detect alterations (MD5, SHA-256)
  • Version Control: Track changes, revert if needed (Git)
  • Audit Trails: Log who changed what and when
  • Backups: 3-2-1 backup rule

Protecting Availability

  • Hardware Maintenance: Regular updates, replace aging equipment
  • Network Management: Reliable infrastructure, load balancing
  • Disaster Recovery: Plans for floods, fires, cyber attacks
  • Redundant Systems: Dual PSUs, multiple NICs, RAID, failovers
  • DDoS Protection: Rate limiting, CDNs, firewalls

Exam Tip

When asked about CIA Triad, always explain:

  1. What the principle means
  2. What threatens it
  3. How to protect it

8.4.2 IAAA Security Model

The Four Components

Identification

Who are you?

Example: Username, email, employee ID

Purpose: Claim an identity

Authentication

Prove who you are

Example: Password, fingerprint, security token

Purpose: Verify the claimed identity

Authorization

What can you access?

Example: Role-based access control (RBAC)

Purpose: Grant appropriate permissions

Auditing/Accounting

What did you do?

Example: Audit logs, activity monitoring

Purpose: Track actions for security and compliance

Multi-Factor Authentication (MFA)

Something you know: Password, PIN

Something you have: Phone, security token, smart card

Something you are: Fingerprint, face ID, iris scan

Why MFA? Even if password is stolen, attacker needs the other factor(s)

Role-Based Access Control (RBAC)

Assign permissions based on job roles, not individuals

Example: Receptionist can only book appointments, not access medical records

Benefits:

  • Principle of Least Privilege (only what's needed)
  • Easier to manage (change role, not individual permissions)
  • Reduces insider threats
  • Compliance with regulations

Audit Logs Should Capture

  • Who: User ID, account name
  • What: Action performed (accessed database, deleted file)
  • When: Timestamp (date and time)
  • Where: IP address, device, location
  • Result: Success or failure

Exam Scenario: Impossible Travel

Problem: Account logs in from London at 9:00 AM, then New York at 9:30 AM

Why it's a threat: Physically impossible - credentials compromised

Actions:

  1. Lock/suspend the account immediately
  2. Force password reset
  3. Enable/enforce MFA
  4. Investigate what data was accessed

8.3.1 Threat Mitigation Techniques

Physical Access Controls

Entry Controls

  • Access levels to doors
  • Key cards, biometric scanners
  • Turnstiles, mantraps

Surveillance

  • CCTV cameras
  • Security guards
  • Motion detectors

Environmental Controls

  • Fire suppression
  • Climate control
  • Flood detection

Device Security

  • Cable locks for laptops
  • Locked server racks
  • Asset tracking

Password Policies

Strong Password Requirements

  • Length: Minimum 12-16 characters
  • Complexity: Mix of uppercase, lowercase, numbers, symbols
  • Avoid: Dictionary words, personal info, common patterns
  • Best Practice: Use passphrases (short stories) or password managers

Why strong passwords? Longer to crack, resists brute force attacks

File Permissions & Access Levels

File Permissions

Controls what users can do with specific files

Types: Read, Write, Execute, Delete

Example: Marketing team can read sales data but not edit it

Access Levels

Controls what users can do on the system

Types: Standard user, Power user, Administrator

Example: Only IT admin can install software or run admin commands

Backup & Recovery

Implications of Poor Backup Procedures

  • Data Loss: Ransomware, hardware failure → all data gone
  • Business Disruption: Cannot operate without data
  • Financial Loss: Ransom payments, lost productivity, customer loss
  • Legal Issues: GDPR violations if personal data is lost
  • Reputation Damage: Loss of customer trust

8.1.3 Impact of Security Failures

Common Threats

Malware

Viruses, worms, trojans, ransomware, spyware

Impact: Data theft, encryption, system damage

Phishing

Fake emails/websites to steal credentials

Impact: Account compromise, data breaches

Social Engineering

Manipulating people to reveal information

Impact: Unauthorized access, data leaks

Insider Threats

Malicious or negligent employees

Impact: Data theft, sabotage

DDoS Attacks

Overwhelming servers with traffic

Impact: Service unavailability, lost revenue

SQL Injection

Exploiting database vulnerabilities

Impact: Data theft, database corruption

Privacy & Confidentiality Failures

Consequences for Organizations

  • Legal Penalties: GDPR fines up to €20M or 4% of global revenue
  • Reputation Damage: Loss of customer trust and brand value
  • Financial Loss: Compensation, legal fees, lost business
  • Operational Disruption: Systems offline, investigation costs
  • Customer Churn: Customers switch to competitors

Consequences for Individuals

  • Identity Theft: Stolen personal data used for fraud
  • Financial Loss: Unauthorized transactions, credit damage
  • Privacy Violation: Personal information exposed
  • Stress & Anxiety: Emotional impact of breach

Case Study: Stuxnet

Sophisticated malware that targeted Iranian nuclear facilities

  • Method: Worm spread via USB drives, exploited Windows zero-days
  • Target: Siemens SCADA systems controlling centrifuges
  • Impact: Physically damaged centrifuges, set back nuclear program
  • Lesson: Air-gapped systems are not immune, physical damage possible

Exam Strategy & Tips

Question Types

State/Identify (1-2 marks)

Brief answer, no explanation

Example: "State two types of changeover methods"

Answer: Direct and Parallel

Describe/Explain (3-4 marks)

More detail, show understanding

Example: "Explain how MFA improves security"

Answer: Define MFA, give example, explain benefit

Discuss (6-8 marks)

Pros and cons, multiple points

Example: "Discuss the use of parallel changeover"

Answer: Explain method, advantages, disadvantages, context

Evaluate (10-12 marks)

Analysis, judgment, supported conclusion

Example: "Evaluate security techniques"

Answer: Multiple techniques, strengths/limitations, make judgment

Command Words

Command What to Do Example
State Give brief answer without explanation "Confidentiality"
Identify Name or select correct answer "HTTPS"
Describe Give characteristics or features "MFA requires multiple forms of verification..."
Explain Give reasons WHY something happens "MFA is secure BECAUSE even if password is stolen..."
Discuss Present multiple viewpoints Advantages AND disadvantages
Evaluate Judge the effectiveness, make a conclusion Analyze strengths/weaknesses, conclude which is best
Compare Show similarities and differences "Both use..., but X is faster while Y is safer"

Common Exam Mistakes to Avoid

1. Not Reading the Question Properly

Always identify:

  • Command word (explain vs. discuss vs. evaluate)
  • Context (what type of organization?)
  • How many marks (affects detail needed)
  • How many points needed (usually marks/2)

2. No Context

Bad: "Parallel is good because it's safe"

Good: "Parallel changeover would be appropriate for the bank's payroll system because if the new system fails, they can continue using the old system and ensure employees are still paid correctly"

3. Listing Without Explaining

Bad: "CIA Triad is confidentiality, integrity, availability"

Good: "Confidentiality ensures only authorized staff can access patient records. This is achieved through encryption and access controls, protecting sensitive medical data from unauthorized disclosure"

4. Ignoring the Marks

  • 2 marks: Brief point, maybe one sentence
  • 4 marks: Two detailed points with explanation
  • 6 marks: Three points with context and examples
  • 12 marks: Multiple points, strengths/weaknesses, judgment

5. No Justification in Evaluate Questions

Always end evaluate questions with a supported judgment:

Example: "Overall, MFA is the most critical security technique because it prevents 99.9% of account compromises, making it more effective than password policies alone"

6. Technical Terms Without Definition

First time you use a term, define it briefly:

Example: "The organization should implement RBAC (Role-Based Access Control), which assigns permissions based on job roles rather than individuals..."
