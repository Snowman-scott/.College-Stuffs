🧩 1.1 Computational Thinking

Computational thinking is a problem-solving approach that involves breaking down complex problems into manageable parts.

Decomposition

Breaking down a complex problem into smaller, more manageable sub-problems

Example: Creating a login system → username validation, password checking, session management

Pattern Recognition

Identifying similarities or patterns within problems

Abstraction

Example: Using a car - you don't need to know how the engine works, just how to drive

Algorithm Design

Creating step-by-step solutions to problems

Example: Recipe for making tea - specific ordered steps

📊 1.2 Algorithms

Searching Algorithms ▼

Linear Search

Checks each element one by one from start to finish

  • Time Complexity: O(n)
  • Best Case: O(1) - item is first
  • Worst Case: O(n) - item is last or not present
  • Use When: Small datasets or unsorted data
def linear_search(arr, target): for i in range(len(arr)): if arr[i] == target: return i # Return index if found return -1 # Not found

Binary Search

Divides sorted list in half repeatedly to find target

  • Time Complexity: O(log n)
  • Requirement: List MUST be sorted
  • Use When: Large sorted datasets
def binary_search(arr, target): left, right = 0, len(arr) - 1 while left <= right: mid = (left + right) // 2 if arr[mid] == target: return mid elif arr[mid] < target: left = mid + 1 else: right = mid - 1 return -1 # Not found
Sorting Algorithms ▼

Bubble Sort

Repeatedly swaps adjacent elements if they're in wrong order

  • Time Complexity: O(n²)
  • Space Complexity: O(1)
  • Stable: Yes
  • Use When: Small datasets, educational purposes
def bubble_sort(arr): n = len(arr) for i in range(n): for j in range(0, n-i-1): if arr[j] > arr[j+1]: arr[j], arr[j+1] = arr[j+1], arr[j] return arr

Merge Sort

Divide and conquer - splits array, sorts, then merges

  • Time Complexity: O(n log n)
  • Space Complexity: O(n)
  • Stable: Yes
  • Use When: Need guaranteed O(n log n), external sorting

Quick Sort

Picks a pivot, partitions array around it

  • Average Time: O(n log n)
  • Worst Case: O(n²)
  • Space Complexity: O(log n)
  • Use When: General purpose, in-memory sorting
Algorithm Time (Best) Time (Average) Time (Worst) Space Bubble Sort O(n) O(n²) O(n²) O(1) Merge Sort O(n log n) O(n log n) O(n log n) O(n) Quick Sort O(n log n) O(n log n) O(n²) O(log n)
🎯 Quick Quiz: Which algorithm would you choose?

You need to search for a student's record in a database of 10,000 students sorted by student ID. Which algorithm is most efficient?

A) Linear Search - check each student one by one
B) Binary Search - divide and conquer the sorted list
C) Bubble Sort - sort then search
D) Just guess randomly
Explanation: Binary Search is O(log n) which is much faster than Linear Search's O(n) for large datasets. Since the list is already sorted, Binary Search can find the record in about 13 comparisons (log₂ 10000 ≈ 13) vs. potentially 10,000 with Linear Search!

📈 1.3 Data Structures

Arrays

Fixed-size collection of elements of same type

Access: O(1) - Direct index access

Insert/Delete: O(n) - May need to shift elements

Use When: Size known, frequent access by index

# Python list (dynamic array) students = ["Alice", "Bob", "Charlie"] print(students[1]) # Bob - O(1)

Linked Lists

Elements linked via pointers, dynamic size

Access: O(n) - Must traverse from head

Insert/Delete: O(1) - If you have the reference

Use When: Frequent insertions/deletions

class Node: def __init__(self, data): self.data = data self.next = None

Stacks (LIFO)

Last In, First Out - like a stack of plates

Operations: push(), pop(), peek()

Use When: Undo functions, recursion, backtracking

stack = [] stack.append(1) # push stack.append(2) # push stack.pop() # returns 2

Queues (FIFO)

First In, First Out - like a line/queue

Operations: enqueue(), dequeue(), peek()

Use When: Task scheduling, breadth-first search

from collections import deque queue = deque() queue.append(1) # enqueue queue.popleft() # dequeue

Hash Tables

Key-value pairs with hash function for fast lookup

Access/Insert/Delete: O(1) average

Use When: Need fast lookups, dictionaries

# Python dictionary student_grades = { "Alice": 95, "Bob": 87 } print(student_grades["Alice"])

Trees

Hierarchical structure with nodes and edges

Binary Tree: Each node has max 2 children

BST: Left < Parent < Right

Use When: Hierarchical data, fast search

📦 2.4 Object-Oriented Programming

Four Pillars of OOP

1. Encapsulation

Bundling data and methods together, hiding internal details

2. Inheritance

Creating new classes based on existing ones

3. Polymorphism

Same interface, different implementations

4. Abstraction

Hiding complex implementation details

# Basic Class class Student: def __init__(self, name, age): self.name = name self.age = age self.grades = [] def add_grade(self, grade): self.grades.append(grade) def get_average(self): if len(self.grades) == 0: return 0 return sum(self.grades) / len(self.grades) def display_info(self): print(f"{self.name} ({self.age})") print(f"Average: {self.get_average():.2f}") # Create objects student1 = Student("Alice", 20) student1.add_grade(85) student1.add_grade(90) student1.display_info() # Inheritance class GraduateStudent(Student): def __init__(self, name, age, thesis_topic): super().__init__(name, age) # Call parent constructor self.thesis_topic = thesis_topic def display_info(self): super().display_info() # Call parent method print(f"Thesis: {self.thesis_topic}") grad = GraduateStudent("Bob", 25, "AI Research") grad.display_info()

🔒 4.1 Data Protection Act 2018 (DPA) & UK GDPR

What is GDPR?

General Data Protection Regulation - EU law protecting personal data and privacy, implemented in UK law via the Data Protection Act 2018

The 7 Key Principles of GDPR ▼
  1. Lawfulness, Fairness, Transparency: Process data legally, fairly, and openly
  2. Purpose Limitation: Collect data for specific, stated purposes only
  3. Data Minimization: Only collect what's necessary
  4. Accuracy: Keep data accurate and up to date
  5. Storage Limitation: Don't keep data longer than needed
  6. Integrity & Confidentiality: Keep data secure
  7. Accountability: Demonstrate compliance
Individual Rights Under GDPR ▼
  • Right to be Informed: Know how data is used
  • Right of Access: Request copy of your data (Subject Access Request)
  • Right to Rectification: Correct inaccurate data
  • Right to Erasure: "Right to be forgotten" - delete data
  • Right to Restrict Processing: Limit how data is used
  • Right to Data Portability: Transfer data to another service
  • Right to Object: Stop certain processing
  • Rights re Automated Decisions: Not subject to automated decisions alone

GDPR Penalties

Serious breaches: Up to €20 million or 4% of global annual turnover (whichever is higher)

Less serious: Up to €10 million or 2% of global annual turnover

Example: British Airways fined £20 million for 2018 data breach

    • 🔄 5.3 Changeover Methods

    Direct Changeover ▼

    Description: Old system stops, new system starts immediately on a specific date

    ✅ Advantages

    • Fast implementation: Instant switch
    • Low cost: No overlap period
    • Immediate benefits: Start using new features right away
    • Forces commitment: No turning back

    ❌ Disadvantages

    • High risk: If new system fails, big problems
    • No fallback: Can't revert to old system easily
    • Staff pressure: Must learn quickly
    • Potential disruption: Business may stop

    🎯 Best for: Simple systems, moving from paper to digital, non-critical systems

    Example: Dental practice moving from paper appointment book to digital system

    Parallel Changeover ▼

    Description: Both old and new systems run simultaneously for a period

    ✅ Advantages

    • Very safe: Can compare outputs
    • Easy fallback: Old system still working
    • Verify accuracy: Check new system is correct
    • Gradual transition: Staff have time to learn

    ❌ Disadvantages

    • Very expensive: Running two systems
    • Double workload: Enter data twice
    • Slow transition: Takes longer
    • Staff fatigue: Doing everything twice

    🎯 Best for: Critical systems (payroll, banking), high-risk changes

    Example: Bank implementing new payment processing system

    Pilot Changeover ▼

    Description: Trial with small group/department before full rollout

    ✅ Advantages

    • Test before full deployment: Find issues early
    • Limited impact: Only affects pilot group
    • Gather feedback: Real user experiences
    • Train champions: Pilot users help others later

    ❌ Disadvantages

    • Time consuming: Pilot then full rollout
    • Pilot may not represent all: Different user needs
    • No full load testing: Can't test with all users
    • Two-stage process: Longer overall timeline

    🎯 Best for: Large organizations, multi-site deployments, complex systems

    Example: University testing new enrollment system with one department

    Phased Changeover ▼

    Description: System introduced in stages/modules over time

    ✅ Advantages

    • Manageable chunks: One module at a time
    • Fix issues per phase: Before moving on
    • Gradual learning: Staff not overwhelmed
    • Spread costs: Pay as you implement

    ❌ Disadvantages

    • Longest implementation: Takes most time
    • Integration issues: Modules may not work together well initially
    • Complex planning: Must decide order carefully
    • Prolonged change period: Disruptive for longer

    🎯 Best for: Complex systems with distinct modules, modular software

    Example: ERP system - implement HR module, then Finance, then Inventory

    🎯 Changeover Methods Quiz

    A hospital is implementing a new patient records system. Lives depend on accurate data. Which changeover method should they use?

    A) Direct - switch immediately for instant benefits
    B) Parallel - run both systems to ensure accuracy and safety
    C) Pilot - test with one ward first

    Correct! Parallel changeover is best for critical systems where accuracy is vital. The hospital can compare outputs between old and new systems to ensure patient data is correct before fully switching. The double workload and cost are worth it when lives are at stake.

    ⚠️ 5.4 Risk Management

    Strategic Risks

    Business decisions, market changes, competition

    Example: Choosing wrong technology stack for project

    Operational Risks

    Day-to-day failures, system downtime

    Example: Server crashes during peak hours

    Financial Risks

    Budget overruns, cash flow issues

    Example: Project costs exceed budget by 50%

    Compliance Risks

    Legal violations, regulatory failures

    Example: GDPR breach, data loss

    Risk Management Process

    1. Identify: What could go wrong?
    2. Assess: How likely? How severe? (Risk matrix: Likelihood × Impact)
    3. Mitigate:
      • Avoid: Don't do the risky activity
      • Reduce: Take steps to minimize impact
      • Transfer: Insurance, outsourcing
      • Accept: Accept risk and plan for consequences
    4. Monitor: Track risks continuously
    5. Review: Update assessments regularly

    ⚠️ Security Threat Detected

    Why this is a threat: Physically impossible to travel London → New York in 30 minutes. Credentials have been compromised!

    Immediate Actions:

    1. Lock Account: Stop attacker accessing more data
    2. Force Password Reset: Invalidate stolen credentials
    3. Enable MFA: Require second factor for future logins
    4. Investigate: What data was accessed? Notify affected users
    5. Review Logs: Check for other suspicious activity

    What's the difference between Bandwidth, Latency, and Throughput?

    👆 Click to reveal

    ✅ Answer

    Bandwidth: Maximum capacity (highway width) - measured in bps

    Latency: Delay before transfer starts (journey start time) - measured in ms

    Throughput: Actual data transferred (≤ bandwidth) - affected by real-world conditions

    👆 Click to flip back

    Bandwidth

    The maximum amount of data that can be transmitted

    Analogy: Width of highway - more lanes = more capacity

    Measured in: bps, Mbps, Gbps

    Latency

    The delay before data transfer begins

    Analogy: Time to start journey

    Measured in: milliseconds (ms)

    Throughput

    The actual data transmitted successfully

    Analogy: Cars that complete journey

    Note: Always ≤ Bandwidth

    Factors Affecting Throughput

    • Connection Quality: Latency, packet loss, jitter
    • Network Congestion: More users = slower speeds
    • Network Type: Fiber vs copper vs wireless
    • Access Point Config: Device limits, range, coverage
    • Interference: Physical obstacles, electromagnetic interference

    🔒 Content Area 8: Security

    🛡️ 8.1 CIA Triad

    Confidentiality

    Information accessible only to authorized users

    Protect with:

    • Encryption
    • Access controls
    • Data classification
    • Physical security

    Threats: Data breaches, eavesdropping

    Integrity

    Information remains accurate and unaltered

    Protect with:

    • Checksums/Hashes
    • Version control
    • Audit trails
    • Data validation
    • Backups (3-2-1)

    Threats: Data corruption, unauthorized modifications

    Availability

    Information accessible when needed

    Protect with:

    • Hardware maintenance
    • Network management
    • Disaster recovery
    • Redundant systems
    • Load balancing

    Threats: DDoS attacks, hardware failures

    🔐 8.4.2 IAAA Security Model

    Identification

    Who are you?

    Claim an identity

    Examples:

    • Username
    • Email address
    • Employee ID

    Authentication

    Prove who you are

    Verify the claimed identity

    Examples:

    • Password
    • Fingerprint
    • Security token
    • MFA

    Authorization

    What can you access?

    Grant appropriate permissions

    Examples:

    • RBAC
    • File permissions
    • Access levels

    Auditing

    What did you do?

    Track actions

    Log:

    • Who
    • What
    • When
    • Where
    • Result

    Multi-Factor Authentication (MFA)

    Require multiple forms of verification:

    • Something you know: Password, PIN
    • Something you have: Phone, security token, smart card
    • Something you are: Fingerprint, face ID, iris scan

    Why MFA? Even if password is stolen, attacker needs the other factor(s). Prevents 99.9% of account compromises!

    Role-Based Access Control (RBAC) ▼

    Concept: Assign permissions based on job roles, not individuals

    Example:

    • Receptionist: Book appointments, view patient contact info
    • Nurse: View medical records, update vitals
    • Doctor: Full access to medical records, prescribe medication
    • IT Admin: System configuration, user management

    Benefits:

    • Principle of Least Privilege: Only what's needed
    • Easier Management: Change role, not individual permissions
    • Reduces Insider Threats: Limited access
    • Compliance: Meets regulatory requirements

    🚨 8.3.1 Threat Mitigation

    Physical Access Controls ▼

    Entry Controls

    • Access levels to doors
    • Key cards, biometric scanners
    • Turnstiles, mantraps
    • Security guards

    Surveillance

    • CCTV cameras
    • Motion detectors
    • Visitor logs
    • Badge systems
    Password Policies ▼

    Strong Password Requirements

    • Length: Minimum 12-16 characters
    • Complexity: Mix of uppercase, lowercase, numbers, symbols
    • Avoid: Dictionary words, personal info, common patterns
    • Best Practice: Use passphrases or password managers
    • Regular Changes: Update periodically
    • No Reuse: Different passwords for different accounts

    Why? Longer passwords take much longer to crack. 8 characters = minutes, 16 characters = centuries!

    🎯 Security Quiz

    A company database is accessible to all staff. An IT admin accidentally deletes critical customer records. Which CIA principle was violated?

    A) Confidentiality - data was exposed
    B) Integrity - data was altered/deleted incorrectly
    C) Availability - data is unavailable
    D) All of the above
    Primary violation: Integrity! The data was altered (deleted) incorrectly. While it also affects Availability (can't access deleted data), the root issue is Integrity - data should remain accurate and unaltered. This could have been prevented with proper access controls (RBAC) and backups!

    Implications of Poor Backup & Recovery

    • Data Loss: Ransomware, hardware failure → all data gone permanently
    • Business Disruption: Cannot operate without data
    • Financial Loss: Ransom payments, lost productivity, customer loss
    • Legal Issues: GDPR violations if personal data is lost
    • Reputation Damage: Loss of customer trust
    • Competitive Disadvantage: Rivals gain advantage

    🔧 Employer Set Project (ESP) Guide

    What is the ESP?

    The Employer Set Project (ESP) is a substantial real-world project where you demonstrate your software development skills by creating a software solution for an actual employer/client.

    Duration: Typically 8-10 weeks

    Assessment: Externally assessed by Pearson (60% of Occupational Specialism grade)

    Real Client: You work with a real employer who sets the brief and provides feedback throughout

    📋 ESP Project Phases

    Phase 1: Planning (10%) ▼

    What You Need to Do:

    • Understand the Brief: Read and analyze client requirements
    • Research: Investigate similar solutions, technologies, approaches
    • Requirements Analysis: Functional and non-functional requirements
    • Project Plan: Timeline, milestones, resources needed
    • Risk Assessment: Identify potential risks and mitigation strategies
    • Design Ideas: Initial sketches, wireframes, system architecture

    Tips for Success:

    • Document everything - keep detailed notes of research
    • Create a realistic project plan with buffer time
    • Consider both technical and user requirements
    • Think about testing strategy from the start
    Phase 2: Design (15%) ▼

    Design Documentation:

    • System Architecture: Overall structure (frontend, backend, database)
    • Database Design: ER diagrams, table structures, relationships
    • UI/UX Design: Wireframes, mockups, user flow diagrams
    • Algorithms: Flowcharts or pseudocode for complex logic
    • Data Structures: How data will be organized and stored
    • Testing Plan: Test cases, acceptance criteria
    • Security Considerations: How will you protect data?

    Design Tools:

    • Wireframing: Figma, Adobe XD, Balsamiq
    • Database: Draw.io, Lucidchart for ER diagrams
    • Flowcharts: Draw.io, Lucidchart
    • Version Control: Git/GitHub for code and documentation
    Phase 3: Development (50%) ▼

    Implementation:

    • Code Quality: Clean, well-structured, commented code
    • Version Control: Regular commits with meaningful messages
    • Follow Standards: Coding conventions, naming conventions
    • Iterative Development: Build features incrementally
    • Testing as You Go: Unit tests, integration tests
    • Client Feedback: Show progress, get feedback, iterate
    • Documentation: Code comments, README files

    Common Pitfalls to Avoid:

    • ❌ Leaving everything to the last minute
    • ❌ Not testing until the end
    • ❌ Ignoring security best practices
    • ❌ Poor code organization
    • ❌ No error handling
    • ❌ Hardcoded values instead of configuration
