Analysis to Identify Patterns

🔍 Finding Meaningful Insights in Data

Pattern analysis involves examining data to discover recurring trends, relationships, and anomalies that provide business insights and inform strategic decisions.

🛒

Customer Behaviour Patterns

  • Purchase Patterns: When, what, and how often customers buy
  • Browsing Behaviour: Which products viewed, time spent
  • Cart Abandonment: Why customers don't complete purchases
  • Seasonal Trends: Demand fluctuations throughout the year
  • Customer Segmentation: Grouping similar customer behaviours
📈

Sales & Revenue Patterns

  • Sales Cycles: Peak and slow periods
  • Product Performance: Best and worst sellers
  • Geographic Patterns: Regional sales variations
  • Correlation Analysis: What factors drive sales
  • Forecasting: Predicting future sales trends

Example: Tesco Clubcard Analysis

Tesco analyses millions of transactions to identify purchasing patterns: families buy nappies with beer on Friday nights, health-conscious shoppers buy organic vegetables with vitamins, ready-meal buyers shop on weekday evenings. These patterns drive product placement, promotional timing, and personalised vouchers.

📊 Trend Analysis

Load Analysis & Capacity Planning

📊 Understanding System Resource Usage

Load analysis measures how much of system capacity is being used—CPU, memory, disk, network—to ensure adequate resources and identify when scaling is needed.

Key Load Metrics

  • CPU Usage: Percentage of processor capacity used (aim for <70% average)
  • Memory Utilisation: RAM consumption (high memory = slow performance)
  • Disk I/O: Read/write operations per second
  • Network Bandwidth: Data transfer rates
  • Concurrent Users: Number of simultaneous active sessions
  • Queue Length: Requests waiting to be processed

Load Patterns

Normal Load

System operating within designed capacity, responsive performance

High Load

Approaching capacity limits, performance degradation begins, plan scaling

Overload

Exceeds capacity, severe slowdown or failures, immediate action needed

Example: Netflix Load Management

Netflix analyses load patterns to predict peak viewing times (evenings, weekends, when popular shows release). They pre-position content on edge servers in high-demand areas and scale cloud infrastructure automatically to handle spikes—ensuring smooth streaming for 230M+ subscribers worldwide.

Outage Detection & Prevention

⚠️ Minimising Service Disruption

Outage analysis tracks service availability, identifies causes of failures, and implements preventive measures to maintain uptime and meet SLA commitments.

Types of Outages

  • Complete Outage: Service entirely unavailable
  • Partial Outage: Some features/regions affected
  • Degraded Performance: Service slow but functional
  • Planned Maintenance: Scheduled downtime for updates

Common Causes

  • Hardware Failure: Server/disk crashes
  • Software Bugs: Code errors causing crashes
  • Network Issues: Connectivity problems
  • Capacity Exceeded: Traffic overwhelms systems
  • Security Incidents: DDoS attacks, breaches
  • Human Error: Misconfiguration, accidents

Outage Metrics

  • Uptime Percentage: 99.9% = 8.76 hours downtime/year
  • MTBF (Mean Time Between Failures): Average time before next outage
  • MTTR (Mean Time To Repair): Average resolution time
  • Incident Frequency: How often problems occur

Prevention Strategies

  • Redundancy - backup systems automatically take over
  • Health checks - continuous monitoring alerts issues early
  • Load balancing - distribute traffic across multiple servers
  • Automated failover - switch to backup instantly
  • Regular maintenance - patch and update during low-traffic periods

⚠️ Example: AWS Outage Impact

In December 2021, a major AWS outage affected numerous services including Netflix, Disney+, and Amazon itself. The incident highlighted the importance of multi-region redundancy—companies relying on a single AWS region faced complete service disruption.

Throughput Measurement & Optimisation

⚡ How Much Work Gets Done?

Throughput measures the volume of work a system processes in a given time period. Higher throughput means more transactions, requests, or data processed efficiently.

Throughput Metrics by System

  • Web Servers: Requests per second (RPS)
  • Databases: Queries per second, transactions per minute
  • Networks: Megabits per second (Mbps), packets per second
  • E-commerce: Orders processed per hour
  • Payment Systems: Transactions per second (TPS)
  • Manufacturing: Units produced per shift

Factors Affecting Throughput

  • System Capacity: Hardware specifications
  • Bottlenecks: Slowest component limits overall speed
  • Concurrency: Parallel processing vs sequential
  • Efficiency: Code optimisation, caching
  • Network Latency: Data transfer delays
  • Database Indexing: Query performance

Example: Visa Payment Network

Visa's network handles an average of 1,700 transactions per second with peak capacity exceeding 65,000 TPS. They continuously monitor throughput to ensure instant payment authorisation globally, optimising database queries, network routing, and server capacity to maintain performance during Black Friday and holiday shopping peaks.

Optimisation Strategies

• Database query optimisation and indexing • Content Delivery Networks (CDNs) for static assets • Caching frequently accessed data • Load balancing across multiple servers • Asynchronous processing for non-critical tasks • Code profiling to identify slow functions

Status Monitoring & Health Checks

✓ Is Everything Working?

Status monitoring continuously checks whether system components are operational, healthy, and performing within expected parameters. It provides real-time visibility into infrastructure health.

What is Monitored

  • Service Availability: Is it up or down?
  • Response Time: How fast does it respond?
  • Error Rates: How many failures?
  • Resource Health: CPU, memory, disk OK?
  • Dependencies: Are external services working?

Monitoring Methods

  • Health Check Endpoints: Regular pings to verify service
  • Synthetic Monitoring: Automated test transactions
  • Real User Monitoring: Actual user experience data
  • Log Analysis: Examine error logs
  • Alerting: Notifications when issues detected

Status Dashboards

Operational

All systems functioning normally

Degraded

Performance issues, investigating

Outage

Service unavailable, incident response active

Example: GitHub Status Page

GitHub maintains a public status page (githubstatus.com) showing real-time status of Git operations, API, webhooks, and other services. Subscribers receive alerts about incidents, and GitHub posts updates during outages—transparency builds trust with developers worldwide.

User Monitoring

👥 Tracking User Activity

User monitoring involves logging and analysing how users interact with systems—when they log in/out, which resources they access, and how they use applications. This data serves security, compliance, and optimisation purposes.

🔐

Security Benefits

  • Anomaly Detection: Spot unusual access patterns (login from unexpected location)
  • Unauthorised Access: Identify attempts to access restricted resources
  • Audit Trails: Track who accessed what and when
  • Compliance: Meet regulatory logging requirements (GDPR, SOX)
📊

Operational Benefits

  • Usage Patterns: Understand peak times and popular features
  • Resource Planning: Allocate capacity based on demand
  • User Experience: Identify pain points and bottlenecks
  • Licence Management: Ensure software licence compliance

⚠️ Privacy Considerations

User monitoring must balance security/operational needs with privacy rights. Under GDPR, users must be informed about monitoring, data should be minimised to what's necessary, and access to monitoring data should be restricted. Avoid excessive surveillance that violates employee privacy or customer trust.

Login/Logout Tracking

🔓 Authentication Event Monitoring

Tracking login and logout events provides critical security data and usage insights, helping identify unauthorised access attempts and understand user activity patterns.

What is Logged

  • Timestamp: Exact date and time of login/logout
  • User ID: Which account was accessed
  • IP Address: Where the connection originated
  • Device Information: Computer, phone, browser type
  • Location: Geographic location (from IP)
  • Success/Failure: Was authentication successful?
  • Session Duration: How long user was logged in

Use Cases

Security Alert Example

Normal: User logs in from London at 9 AM

Suspicious: Same user logs in from Romania 2 hours later

Action: Alert triggered, account locked, user notified

Usage Pattern Example

Company analyses login times: 80% of employees log in between 8-9 AM, creating network congestion. Solution: Stagger start times or upgrade bandwidth during peak hours.

Failed Login Monitoring

Multiple failed login attempts often indicate brute-force attacks. Systems typically lock accounts or add delays after 3-5 failed attempts. Security teams monitor for patterns like many failed attempts across different accounts (credential stuffing attack).

Resources Accessed Monitoring

📂 Tracking What Users Do

Beyond login/logout, organisations monitor which files, databases, applications, and features users access. This ensures security, optimises resource allocation, and provides audit trails.

What is Tracked

  • File Access: Documents opened, edited, downloaded, deleted
  • Database Queries: Which data accessed, by whom, when
  • Application Usage: Which software used, features accessed
  • Web Activity: Sites visited (in corporate environments)
  • Email: Sent/received (metadata, not usually content)
  • Print Jobs: What documents printed
  • API Calls: Which services/endpoints accessed

Security Applications

⚠️ Insider Threat Detection

Scenario: Employee downloads 10,000 customer records to USB drive before resignation

Detection: Unusual data access pattern triggers alert

Action: Security team investigates, prevents data exfiltration

Compliance Use Case

Healthcare: NHS must track who accesses patient records (GDPR, Data Protection Act). If a celebrity's medical records are accessed by unauthorised staff, audit logs identify the violation for disciplinary action.

Example: Google Workspace Admin Console

Administrators can see detailed logs: which documents users created/shared, when they accessed Gmail, which Drive files were downloaded. This helps identify suspicious activity (e.g., mass file downloads before employee departure) and optimise licences (remove inactive users).

Targeted Marketing

🎯 Personalised Marketing Using Data

Targeted marketing uses customer data to deliver personalised messages, offers, and recommendations to specific individuals or segments, increasing relevance and conversion rates whilst reducing wasted marketing spend.

Data Used for Targeting

  • Purchase History: What they've bought before
  • Browsing Behaviour: Products viewed, time spent
  • Demographics: Age, location, income
  • Preferences: Stated interests, communication choices
  • Cart Abandonment: Items added but not purchased
  • Email Engagement: Open rates, click-through rates
  • Lifecycle Stage: New customer, loyal, at-risk

Benefits vs Untargeted Marketing

Untargeted: Send same email to all 100,000 customers

• 2% conversion rate = 2,000 sales

• 98% receive irrelevant messages

• High unsubscribe rates

Targeted: Segment customers, personalise messages

• 8% conversion rate = 8,000 sales

• Customers receive relevant offers

• Lower unsubscribe rates, better engagement

Targeted Discounts & Personalisation

💰 The Right Offer to the Right Person

Rather than offering the same discount to everyone, organisations use data to determine which customers need incentives, which products to discount, and when to send offers for maximum impact.

Discount Targeting Strategies

  • First Purchase Incentive: 15% off for new customers (acquisition)
  • Cart Abandonment: 10% discount sent within 24 hours to complete purchase
  • Win-Back Campaigns: 20% off for inactive customers (not purchased in 3 months)
  • Birthday/Anniversary: Special offer on customer's birthday
  • Price Sensitivity: Bigger discounts to bargain hunters, smaller to loyal customers
  • Category Specific: Discount on products customer has viewed but not bought

Personalisation Beyond Discounts

  • Product Recommendations: "Based on your purchase of X"
  • Content Personalisation: Show running shoes to marathon runners
  • Email Subject Lines: Use customer's name, reference past purchases
  • Timing: Send emails when customer typically opens them
  • Channel Preference: Email vs SMS vs app notification
  • Loyalty Rewards: Points/perks based on spending level

Example: Amazon Personalised Discounts

Amazon analyses your wishlist, viewed items, and cart abandonment. If you've viewed a £50 item three times but haven't purchased, you might receive a £10 voucher specifically for that product category—just enough incentive to convert browsing into a sale without over-discounting.

Upselling & Cross-Selling

⬆️

Upselling

Definition: Encouraging customers to buy a more expensive or upgraded version of what they're considering

Techniques:

  • Feature Comparison: Show benefits of premium version
  • "Customers also considered": Display higher-tier options
  • Limited-Time Upgrades: "Upgrade to Pro for only £5 more today"
  • Social Proof: "90% of customers choose Premium"

Examples

• Airlines: Economy → Premium Economy

• Software: Basic plan → Pro plan

• Cars: Standard model → Luxury trim

• Hotels: Standard room → Suite

➕

Cross-Selling

Definition: Recommending complementary products that enhance the main purchase

Techniques:

  • "Frequently bought together": Show common combinations
  • "Complete the set": Suggest missing items
  • Bundles: Package deals at slight discount
  • Accessories: Essential add-ons for purchased item

Examples

• Camera: + Memory card, lens, bag

• Phone: + Case, screen protector, charger

• Laptop: + Mouse, laptop bag, warranty

• Fast Food: Burger → Add fries and drink

Example: McDonald's "Would you like fries with that?"

This simple cross-sell prompt increases average transaction value by 20-30%. Data shows customers who buy burgers often want fries and drinks—so staff are trained to suggest them. Digital kiosks now use algorithms to recommend optimal combinations based on order history.

Exam-Style Questions

Question 1 (6 marks)

Scenario: An online streaming service notices that their servers experience extremely high load between 7-10 PM every evening, causing buffering and slow performance for users.

Question: Explain how the streaming service could use system performance analysis to address this problem. In your answer, describe:

  • What data they should analyse (2 marks)
  • What solutions they could implement based on this analysis (4 marks)
19 / 25

Question 1: Model Answer

Data to Analyse (2 marks)

The streaming service should analyse load metrics during peak hours including CPU usage, memory utilisation, network bandwidth consumption, and the number of concurrent active streams ✓. They should also examine throughput data (streams per second), response times, buffering rates, and which geographic regions experience the highest demand to identify where capacity issues occur ✓.

Solutions Based on Analysis (4 marks)

The service could implement auto-scaling to automatically add more servers during peak evening hours (7-10 PM) and scale down during quieter periods, reducing costs whilst ensuring adequate capacity when demand is high ✓. They could deploy Content Delivery Networks (CDNs) to cache popular content closer to users geographically, reducing load on central servers and improving streaming quality by serving content from nearby edge locations ✓.

Additionally, they could implement load balancing to distribute incoming streams evenly across multiple servers, preventing any single server from becoming overwhelmed and ensuring consistent performance ✓. Finally, they could offer adaptive bitrate streaming that automatically adjusts video quality based on each user's available bandwidth, allowing more users to stream simultaneously without overwhelming the infrastructure—users with slower connections receive lower quality whilst those with fast connections maintain high quality ✓.

Question 2 (8 marks)

Scenario: A supermarket chain analyses customer transaction data and identifies that 60% of customers who buy nappies also purchase baby food, but only 15% of baby food buyers purchase nappies.

Question: Evaluate how the supermarket could use this pattern analysis for targeted marketing. In your answer, discuss:

  • Two different marketing strategies based on this data (4 marks)
  • The benefits of targeted marketing compared to sending the same offer to all customers (4 marks)
21 / 25

Question 2: Model Answer

Marketing Strategy 1: Cross-Selling to Nappy Buyers (2 marks)

Since 60% of nappy buyers also purchase baby food, the supermarket could target customers buying nappies with personalised vouchers for baby food (e.g., "£1 off baby food with your nappy purchase") ✓. This cross-selling strategy encourages customers to complete their baby shopping in one transaction, increasing basket value. The supermarket could also place baby food displays near nappies in-store or send targeted email offers to online shoppers who add nappies to their cart, capitalising on the established purchasing pattern ✓.

Marketing Strategy 2: Identifying New Parents (2 marks)

The supermarket could identify customers who suddenly start buying baby food but aren't yet purchasing nappies—these are likely new parents whose babies haven't started using solid food yet ✓. The supermarket could proactively send these customers nappy discounts and parenting guides, anticipating their future needs. This targets customers at the right stage in their parenting journey, building loyalty by being helpful before the need arises. Alternatively, they could create "new parent starter bundles" combining both products at a discount to encourage purchasing both items together ✓.

Benefits of Targeted Marketing (4 marks)

Targeted marketing significantly improves conversion rates because customers receive offers relevant to their actual needs ✓—parents with babies are far more likely to use a nappy voucher than childless customers, reducing wasted marketing spend. It increases customer satisfaction and loyalty because personalised offers feel helpful rather than spammy ✓, whereas untargeted mass emails about baby products would annoy customers without children and lead to unsubscribes.

Targeted approaches are more cost-effective as the supermarket saves money by only sending offers to customers likely to respond ✓—instead of mailing 100,000 baby food vouchers to all customers (costing thousands in printing/postage) with low response rates, they send to 10,000 relevant customers with much higher response rates. Finally, targeted marketing based on data insights allows the supermarket to predict future needs and time offers perfectly ✓—sending nappy discounts when a baby is likely transitioning sizes or needs vary, maximising the chance of conversion.

Exam-Style Questions

Question 3 (6 marks)

Scenario: A company's IT department monitors user login activity and notices an employee's account logged in from London at 9:00 AM, then from New York at 9:30 AM the same day.

Question: Explain why this user monitoring data indicates a security threat and describe two actions the company should take in response.

Mark Scheme Guidance:

6 marks total:

  • 2 marks: Clear explanation of why this is suspicious
  • 4 marks: Two appropriate security responses (2 marks each)
23 / 25

Question 3: Model Answer

Why This Indicates a Threat (2 marks)

This login pattern indicates a security threat because it is physically impossible for the same person to travel from London to New York in 30 minutes ✓. This suggests either the employee's credentials (username and password) have been compromised and stolen, or someone is using the employee's account without authorisation—possibly through phishing, password theft, or a previous data breach. One of these logins is definitely unauthorised, indicating the account has been compromised ✓.

Response Action 1: Immediate Account Lockdown (2 marks)

The company should immediately lock or suspend the employee's account to prevent further unauthorised access ✓. This stops the attacker from accessing sensitive company data, systems, or resources whilst the security team investigates. The account should remain locked until security confirms which login was legitimate, the employee's identity is reverified through alternative channels (e.g., phone call), and the password has been reset with multi-factor authentication enabled ✓.

Response Action 2: Investigation and Audit (2 marks)

The IT security team should conduct a full audit of the account's recent activity to determine what data or resources were accessed from the suspicious New York location ✓. They should examine which files were viewed or downloaded, emails sent, systems accessed, and whether any sensitive information was compromised. This audit trail helps assess the damage, identify what data may have been stolen, determine if other accounts are affected, and establish whether this is part of a broader attack. The company should also notify the employee immediately to confirm their actual location and warn them about the compromise ✓.

Summary: How Organisations Use Data

Key Takeaways

  • Pattern Analysis: Organisations identify customer behaviours, sales trends, and market patterns to inform strategy, from market basket analysis to seasonal forecasting
  • System Performance: Continuous monitoring of load, outages, throughput, and status ensures infrastructure reliability, optimal performance, and capacity planning
  • User Monitoring: Tracking login/logout and resource access serves dual purposes—security (detecting unauthorised access, insider threats) and operations (usage patterns, capacity planning)
  • Targeted Marketing: Data-driven personalisation through discounts, upselling, and cross-selling increases conversion rates and customer satisfaction whilst reducing wasted marketing spend
  • Threat Assessment: Analysis of competitor moves, security vulnerabilities, and compliance risks enables proactive risk management and incident prevention
  • Opportunity Assessment: Data reveals market gaps, emerging trends, and growth opportunities—including competitive advantages from compliance and certifications

🎯 Remember

Effective data use requires more than collection—it demands analysis, interpretation, and action. Organisations that successfully leverage data across these categories gain competitive advantages through better decisions, optimised operations, enhanced security, and superior customer experiences. The key is integrating data insights into daily operations and strategic planning.
