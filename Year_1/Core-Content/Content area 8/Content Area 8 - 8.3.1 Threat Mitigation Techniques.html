What is Threat Mitigation?

🛡️ Definition

Threat mitigation encompasses the strategies, techniques, and controls implemented to reduce the likelihood and impact of security threats. It's about building multiple layers of defence to protect systems, data, and users.

🎯

Prevention

Stopping threats before they can cause harm through proactive security measures and controls.

🔍

Detection

Identifying threats that bypass preventive controls through monitoring and alerting systems.

⚡

Response

Reacting quickly to contain and remediate detected threats to minimise damage.

🔄

Recovery

Restoring systems and data to normal operation after a security incident.

Multi-Factor Authentication (MFA)

🔒 Stronger Security Through Multiple Factors

MFA requires users to provide two or more verification factors, making it exponentially harder for attackers to gain unauthorised access.

Why MFA Matters

  • Password Compromise: Even if password is stolen, attacker still needs second factor
  • Phishing Protection: Reduces effectiveness of credential harvesting
  • 99.9% Protection: Microsoft reports MFA blocks 99.9% of automated attacks
  • Compliance: Required by many regulations (PCI DSS, GDPR)

Common MFA Methods

  • SMS Codes: Text message with verification code
  • Authenticator Apps: Time-based codes (Google Authenticator, Microsoft Authenticator)
  • Push Notifications: Approve login on trusted device
  • Hardware Tokens: Physical security keys (most secure)

Authorisation & Access Control

Determining What Users Can Access

After authentication, authorisation controls define what resources users can access and what actions they can perform.

🎭 Role-Based Access Control (RBAC)

Permissions assigned based on job roles

Example: HR staff can access employee records, but not financial systems

  • Simplifies permission management
  • Easier to audit
  • Reduces errors

🔐 Principle of Least Privilege

Users receive minimum access needed

Example: Developers have read-only access to production databases

  • Limits damage from compromised accounts
  • Reduces insider threat risk
  • Meets compliance requirements

Best Practice: Regular Access Reviews

Conduct quarterly reviews to remove unnecessary permissions and ensure access rights remain appropriate for current roles.

Encryption: Data at Rest

🔒 Protecting Stored Data

Data at rest encryption protects information stored on devices, servers, and databases. Even if storage media is stolen, data remains unreadable without decryption keys.

Full Disk Encryption (FDE)

Encrypts entire hard drive or SSD

  • Windows: BitLocker
  • macOS: FileVault
  • Linux: LUKS

Use Case: Laptops, mobile devices, removable media

Database Encryption

Encrypts sensitive database fields or entire databases

  • Column-level: Specific sensitive fields (credit cards, NHS numbers)
  • Transparent Data Encryption: Encrypts entire database files

Use Case: Protecting customer PII, payment data

⚠️ Key Management is Critical

Encryption is only as secure as its keys. Store keys separately from encrypted data, use hardware security modules (HSMs) for key storage, and implement key rotation policies.

Encryption: Data in Transit

🌐 Protecting Data During Transmission

Data in transit encryption protects information as it travels across networks, preventing interception and eavesdropping.

TLS/SSL (Transport Layer Security)

What it does:

  • Encrypts web traffic (HTTPS)
  • Authenticates server identity
  • Ensures data integrity

Used by: Websites, email, APIs, file transfers

Implementation:

  • SSL/TLS certificates from trusted CAs
  • TLS 1.2 or 1.3 (older versions deprecated)
  • Strong cipher suites

Visual indicator: Padlock icon in browser

VPN (Virtual Private Network)

Creates encrypted tunnel for all network traffic

Use cases: Remote workers, public Wi-Fi, site-to-site connections

End-to-End Encryption

Only sender and recipient can decrypt messages

Examples: WhatsApp, Signal, encrypted email (PGP)

Network Security: Firewalls

🔥 Network Traffic Gatekeepers

Firewalls monitor and control incoming and outgoing network traffic based on predetermined security rules, acting as a barrier between trusted internal networks and untrusted external networks.

Packet Filtering Firewalls

Examines packets and allows/blocks based on:

  • Source/destination IP addresses
  • Port numbers
  • Protocols (TCP, UDP, ICMP)

Speed: Fast but basic inspection

Stateful Inspection Firewalls

Tracks connection states and context:

  • Monitors active connections
  • Validates packet sequences
  • Blocks unsolicited responses

Security: More intelligent filtering

Next-Generation Firewalls (NGFW)

Advanced features beyond traditional firewalls:

  • Deep Packet Inspection: Examines packet contents, not just headers
  • Application Awareness: Controls specific applications (block Facebook, allow Slack)
  • Intrusion Prevention: Integrated IPS capabilities
  • Threat Intelligence: Blocks known malicious IPs/domains

Intrusion Detection & Prevention Systems

🔍 IDS (Intrusion Detection System)

Function: Monitors network traffic and alerts on suspicious activity

Action: Passive - detects and alerts only

Detection Methods:

  • Signature-based: Matches known attack patterns
  • Anomaly-based: Identifies deviations from normal behaviour
  • Heuristic: Uses rules to identify suspicious patterns

Example: Snort, Suricata

🛡️ IPS (Intrusion Prevention System)

Function: Monitors traffic AND blocks threats automatically

Action: Active - detects and prevents

Prevention Actions:

  • Drop packets: Discard malicious traffic
  • Block connections: Terminate suspicious sessions
  • Modify packets: Remove malicious content

Risk: False positives can block legitimate traffic

Best Practice: IDS + IPS Combination

Use IDS for monitoring and analysis, IPS for automated blocking of known threats. This provides both visibility and protection whilst reducing false positive impacts.

DMZ & Network Segmentation

🌐 DMZ (Demilitarised Zone)

A network segment that sits between the internal trusted network and the external untrusted network (internet), providing an additional layer of security for public-facing services.

Layer 1: External Network (Internet) 🌍

Public internet - untrusted, potential attackers

Layer 2: DMZ (Outer Firewall) 🔥

Public-facing servers: Web servers, email servers, DNS servers, FTP servers

Purpose: If compromised, attackers still can't reach internal network

Layer 3: Internal Network (Inner Firewall) 🔒

Critical internal systems: Database servers, file servers, employee workstations

Protection: Isolated from both internet and DMZ

Network Segmentation Benefits

• Limits lateral movement of attackers • Contains breaches to specific segments • Simplifies compliance auditing • Improves performance through reduced broadcast traffic

Patch Management & Updates

🔧 Closing Security Vulnerabilities

Patch management is the process of identifying, testing, and deploying software updates to fix security vulnerabilities, bugs, and improve functionality.

1. Identify

Monitor vendor security bulletins and vulnerability databases

→

2. Assess

Evaluate severity and applicability to your systems

→

3. Test

Deploy to test environment first

→

4. Deploy

Roll out to production systems

Critical Patch Categories

  • Security Patches: Fix vulnerabilities (highest priority)
  • Critical Updates: Address major bugs affecting stability
  • Feature Updates: New functionality (test thoroughly)

Patch Management Tools

  • Windows: WSUS, Windows Update
  • Linux: apt, yum, automated patching
  • Enterprise: SCCM, Ansible, Puppet

⚠️ WannaCry Example

The 2017 WannaCry ransomware exploited a Windows vulnerability for which a patch had been available for 2 months. Organisations that hadn't patched suffered major disruption. This highlights the critical importance of timely patch deployment.

Backup & Recovery Strategies

💾 The Last Line of Defence

Regular backups ensure data can be recovered after ransomware attacks, hardware failures, natural disasters, or accidental deletion. A backup strategy is essential for business continuity.

3-2-1 Backup Rule

3️⃣

3 Copies

Keep three copies of your data

Original + 2 backups

2️⃣

2 Media Types

Store on two different media types

e.g., local drive + cloud

1️⃣

1 Off-site

Keep one copy off-site

Protection from physical disasters

Backup Types

  • Full: Complete copy of all data (slow, but simple recovery)
  • Incremental: Only changed data since last backup (fast, complex recovery)
  • Differential: Changed data since last full backup (balanced approach)

Recovery Testing

  • Test restores regularly (quarterly minimum)
  • Document recovery procedures
  • Measure Recovery Time Objective (RTO)
  • Verify data integrity after restoration

Security Awareness Training

👥 The Human Firewall

Employees are often the weakest link in security. Regular training transforms users from vulnerabilities into active defenders against social engineering, phishing, and other human-targeted attacks.

Key Training Topics

  • Phishing Recognition: Identifying suspicious emails, links, attachments
  • Password Security: Creating strong passwords, using MFA
  • Social Engineering: Recognising manipulation tactics
  • Physical Security: Tailgating, shoulder surfing, clean desk policy
  • Data Handling: Classification, secure disposal, encryption
  • Incident Reporting: What to do when something seems wrong

Training Methods

  • Mandatory Annual Training: Foundation knowledge for all staff
  • Simulated Phishing: Real-world testing with immediate feedback
  • Role-Based Training: Additional training for high-risk roles (IT, finance, HR)
  • Security Bulletins: Regular updates on emerging threats
  • Lunch & Learns: Engaging sessions on topical threats

Create a Security Culture

Encourage reporting without punishment, celebrate security champions, make security part of onboarding, and provide easy channels for asking security questions.

Monitoring & Logging

👁️ Visibility is Security

Comprehensive logging and continuous monitoring enable detection of suspicious activities, support incident investigation, and provide audit trails for compliance.

What to Log

  • Authentication Events: Login successes/failures, password changes
  • Access Events: File access, permission changes, data exports
  • Network Activity: Connections, traffic patterns, blocked attempts
  • System Changes: Configuration changes, software installations
  • Security Events: Firewall blocks, IDS alerts, antivirus detections

Log Analysis Tools

  • SIEM (Security Information and Event Management): Aggregates and correlates logs
  • Examples: Splunk, ELK Stack, QRadar
  • Automated Alerting: Immediate notification of critical events
  • Dashboards: Real-time visualisation of security posture

⚠️ Log Retention Requirements

GDPR and other regulations often require logs to be retained for specific periods (typically 6-12 months). Ensure adequate storage and secure log protection to prevent tampering.

Defence in Depth

🛡️ Layered Security Approach

Defence in depth uses multiple layers of security controls. If one layer fails, others provide backup protection. No single point of failure exists.

Layer 7: Policies, Procedures & Awareness 📋

Security policies, user training, acceptable use policies, incident response plans

Layer 6: Physical Security 🏢

Building access controls, CCTV, security guards, locked server rooms

Layer 5: Perimeter Security 🔥

Firewalls, IDS/IPS, DMZ, VPN gateways, secure internet connections

Layer 4: Network Security 🌐

Network segmentation, VLANs, internal firewalls, access control lists

Layer 3: Endpoint Security 💻

Antivirus, endpoint detection, host firewalls, patch management

Layer 2: Application Security 📱

Secure coding, input validation, authentication, authorisation controls

Layer 1: Data Security 🔒

Encryption at rest and in transit, data classification, access controls, backups

Case Study: Target Data Breach (2013)

⚠️ The Incident

Attackers compromised 40 million credit card records and 70 million customer records through a third-party HVAC vendor.

How It Happened

  1. Phishing email sent to HVAC vendor
  2. Vendor credentials stolen
  3. Attackers accessed Target's network via vendor connection
  4. Malware installed on point-of-sale systems
  5. Credit card data stolen over several weeks

Failed Mitigations

  • ❌ Vendor had excessive network access
  • ❌ Network segmentation inadequate
  • ❌ Security alerts ignored
  • ❌ FireEye detected malware but wasn't acted upon

Effective Mitigations That Could Have Prevented It

  • Network Segmentation: Vendor access should have been isolated from payment systems
  • Principle of Least Privilege: HVAC vendor didn't need access to payment networks
  • Monitoring & Response: Security alerts should have triggered immediate investigation
  • Third-party Security: Vendor security assessments could have identified weak controls

Exam-Style Questions

Question 1 (6 marks)

Scenario: A financial services company wants to improve security for employee access to their customer database, which contains sensitive financial information.

Question: Explain three different threat mitigation techniques the company could implement to protect access to this database. For each technique, describe how it would reduce security risks.

Mark Scheme Guidance:

2 marks per technique (total 6 marks):

  • 1 mark: Correct identification of mitigation technique
  • 1 mark: Clear explanation of how it reduces risk in this scenario
19 / 24

Question 1: Model Answer

Multi-Factor Authentication (MFA) (2 marks)

The company could implement MFA requiring employees to use both their password and a second factor such as a code from an authenticator app ✓. This would reduce the risk of unauthorised access because even if an attacker steals or guesses an employee's password through phishing or brute force, they would still be unable to access the database without the second authentication factor ✓.

Role-Based Access Control (RBAC) (2 marks)

The company could implement RBAC to ensure employees only have access to the specific customer records they need for their role ✓. For example, customer service staff might only see basic account information whilst financial advisors see complete financial details. This reduces risk by limiting the amount of sensitive data each employee can access, minimising potential damage from compromised accounts or insider threats ✓.

Database Encryption (2 marks)

The company could encrypt the customer database so that sensitive financial information is stored in encrypted form ✓. This would reduce risk because even if an attacker gains unauthorised access to the database files (through SQL injection or stolen credentials), the data would be unreadable without the decryption keys, protecting customer information from data breaches ✓.

Exam-Style Questions

Question 2 (8 marks)

Scenario: A manufacturing company recently suffered a ransomware attack that encrypted critical production data. The company had to halt operations for three days whilst recovering from backups.

Question: Evaluate the effectiveness of implementing the following mitigation techniques to prevent similar incidents in future:

  • Regular patch management
  • Security awareness training for employees
  • Network segmentation
  • Offline backup strategy

In your answer, explain how each technique helps prevent ransomware attacks and discuss any limitations.

21 / 24

Question 2: Model Answer

Regular Patch Management (2 marks): Keeping all systems updated with the latest security patches ✓ closes known vulnerabilities that ransomware often exploits, such as the EternalBlue vulnerability used by WannaCry. However, this technique has limitations as zero-day vulnerabilities (unknown flaws without patches) can still be exploited, and patching requires careful testing to avoid breaking production systems ✓.

Security Awareness Training (2 marks): Training employees to recognise phishing emails and suspicious attachments ✓ is highly effective since most ransomware infections begin with social engineering. Employees become the first line of defence, preventing initial infection. The limitation is that even well-trained users can occasionally fall for sophisticated phishing attempts, and new employees or contractors may not have received training ✓.

Network Segmentation (2 marks): Dividing the network into separate segments (e.g., production systems, office systems, guest Wi-Fi) with firewalls between them ✓ prevents ransomware from spreading across the entire network if one system is infected. This containment limits damage. However, if ransomware infects a system with legitimate access to multiple segments, it can still spread, and misconfigured segmentation may be ineffective ✓.

Offline Backup Strategy (2 marks): Maintaining regular backups that are disconnected from the network (offline or air-gapped) ✓ ensures ransomware cannot encrypt backup files, allowing complete data recovery without paying ransom. The limitation is that backups are only effective if tested regularly, and there may still be data loss between the last backup and the attack, plus recovery takes time during which operations remain disrupted ✓.

Exam-Style Questions

Question 3 (4 marks)

Question: Compare the security benefits of a traditional firewall with a next-generation firewall (NGFW). Explain why an organisation might choose to invest in an NGFW despite the higher cost.

Mark Scheme Guidance:

4 marks total:

  • 2 marks: Explanation of traditional firewall capabilities
  • 2 marks: Explanation of NGFW additional capabilities and justification for investment
  • Quality of comparison demonstrated through appropriate language
23 / 24

Question 3: Model Answer

Traditional firewalls ✓ control traffic based on basic criteria such as IP addresses, port numbers, and protocols. They can block or allow traffic to specific ports (e.g., blocking port 80 for HTTP) but cannot inspect the actual content of the data packets or identify which applications are being used ✓.

In contrast, next-generation firewalls ✓ provide deep packet inspection to examine the actual content of network traffic, not just headers. They can identify and control specific applications (blocking Facebook whilst allowing Slack), detect and prevent intrusion attempts automatically, and incorporate threat intelligence to block connections to known malicious IP addresses and domains. An organisation might justify the higher cost because NGFWs provide much more sophisticated protection against modern threats like advanced malware, targeted attacks, and application-layer exploits that traditional firewalls cannot detect ✓.

Key Comparison Points:

• Traditional: Basic filtering vs NGFW: Intelligent analysis

• Traditional: Port-based vs NGFW: Application-aware

• Traditional: Reactive vs NGFW: Proactive threat prevention

Summary: Threat Mitigation Techniques

Key Takeaways

  • Layered Defence: Defence in depth uses multiple overlapping security controls to ensure no single point of failure
  • Access Control: Authentication (proving identity) and authorisation (controlling permissions) are foundational security controls
  • Encryption: Protects data both at rest and in transit, rendering it unreadable without decryption keys
  • Network Security: Firewalls, IDS/IPS, and network segmentation control and monitor network traffic
  • Proactive Measures: Patch management, backups, and monitoring prevent incidents and enable rapid recovery
  • Human Element: Security awareness training transforms users from vulnerabilities into active defenders
  • Preparedness: Incident response planning ensures coordinated, effective action during security events

🎯 Remember

No single mitigation technique provides complete protection. Effective security requires a combination of technical controls, procedural safeguards, and security-aware users working together as part of a comprehensive defence-in-depth strategy.
