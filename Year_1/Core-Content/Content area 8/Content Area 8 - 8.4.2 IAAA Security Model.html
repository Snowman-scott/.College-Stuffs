Identification: Who Are You?

👤

🔍 Core Concept

Identification is the process of recognising an individual within a digital system. It's the first step in the IAAA model.

The user makes a claim about their identity – "I am user123" or "I am John Smith".

⚠️ Important Distinction

Identification ≠ Authentication

Identification is simply claiming an identity. Authentication is proving that claim is true.

🧠 Knowledge-Based

Something you know (username, email, ID number)

🔑 Possession-Based

Something you have (card, token, device)

👆Biometric-Based

Something you are (fingerprint, face, iris)

Knowledge-Based Identification

Username: john.smith
Email: john.smith@company.com
Employee ID: EMP-2024-1337

🧠 What is Knowledge-Based ID?

Identification using information that the user knows. The most common method in digital systems.

📋 Common Examples

  • Username – Unique identifier (e.g., john.smith)
  • Email address – Often used as identifier
  • Employee/Student ID – Numerical identifiers
  • National Insurance/Social Security number
  • Account numbers – Banking, customer accounts

🎯 Best Practices

  • Use unique identifiers per user
  • Make usernames memorable but not too personal
  • Avoid using sensitive data (DOB, SSN) as primary ID
  • Consider using email for easy recovery

✅ Benefits

  • Simple and easy to implement
  • No special hardware required
  • Familiar to users
  • Low cost
  • Can be changed if compromised

❌ Drawbacks

  • Can be forgotten
  • Can be guessed or leaked
  • Vulnerable to phishing
  • Can be shared (intentionally or not)
  • No proof user is who they claim

Possession-Based Identification

🔑

🔑 What is Possession-Based ID?

Identification using something the user physically possesses. The device or token proves identity.

💳 Smart Cards

Example: Employee ID badges, bank cards with chips

Contains embedded chip with unique identifier

🔐 Security Tokens

Example: USB security keys, hardware tokens (YubiKey, RSA SecurID)

Physical device generates codes or proves presence

📱 Mobile Devices

Example: Smartphone as authenticator, registered device ID

Device-specific identifiers prove possession

✅ Benefits

  • Physical proof of identity
  • Difficult to duplicate
  • Can be combined with other methods
  • Easy to revoke if lost
  • Provides strong security

❌ Drawbacks

  • Can be lost or stolen
  • Requires physical carrying
  • Hardware costs
  • Can be lent to others
  • May require special readers

⚠️ Security Note

Possession-based methods should be combined with other factors (multi-factor authentication) for maximum security!

Biometric-Based Identification

👆

🧬 What is Biometric ID?

Identification using unique physical or behavioural characteristics. Uses "something you are" rather than something you know or have.

👆 Fingerprint

Unique ridge patterns on fingertips

Use: Phones, laptops, building access

👁️ Iris/Retina

Unique patterns in the eye

Use: High-security facilities, borders

😊 Facial Recognition

Unique facial features and geometry

Use: Smartphones, airports, surveillance

🗣️ Voice Recognition

Unique vocal patterns and frequency

Use: Phone banking, voice assistants

✍️ Signature Dynamics

Unique way of signing (pressure, speed)

Use: Document signing, banking

🚶 Gait Analysis

Unique walking pattern

Use: Surveillance, research

✅ Benefits

  • Cannot be forgotten
  • Difficult to fake or steal
  • Convenient (always with you)
  • Unique to each individual
  • Fast identification

❌ Drawbacks

  • Expensive hardware required
  • Privacy concerns
  • Cannot be changed if compromised
  • False positives/negatives
  • Can change over time (age, injury)
  • Hygiene concerns (fingerprint readers)

Authentication: Prove It!

✅

🔐 Core Concept

Authentication is the process of verifying the identity claimed during identification.

The system challenges the user to prove they are who they claim to be.

AUTHENTICATION PROCESS:
[1] User claims identity → "I am john.smith"
[2] System challenges → "Prove it with your password"
[3] User provides proof → Enters password
[4] System verifies → Compares against stored hash
[5] Result → ACCESS_GRANTED or ACCESS_DENIED

🔑 Authentication Factors

  • Something you KNOW – Password, PIN, security question
  • Something you HAVE – Phone, token, smart card
  • Something you ARE – Fingerprint, face, iris
  • Somewhere you ARE – GPS location, IP address
  • Something you DO – Typing pattern, behavioural biometrics

⚠️ Why Authentication Matters

Identification alone is not secure – anyone can claim to be someone else. Authentication provides the proof that the claim is legitimate!

Passwords & Passphrases

Password: ••••••••••••
Passphrase: "correct horse battery staple"

🔒 Knowledge-Based Authentication

The most common authentication method – users prove their identity by providing a secret only they should know.

🔑 Passwords

  • Short secret string (8-20 characters)
  • Should be complex: uppercase, lowercase, numbers, symbols
  • Example: P@ssw0rd123!
  • Stored as cryptographic hash

📝 Passphrases

  • Longer phrase or sentence (20+ characters)
  • More memorable than complex passwords
  • Example: "I love coffee in the morning 2024!"
  • Stronger due to length

✅ Benefits

  • Simple and familiar to users
  • No special hardware needed
  • Can be changed easily
  • Works on any device
  • Low cost to implement

❌ Drawbacks

  • Users choose weak passwords
  • Vulnerable to brute force attacks
  • Can be guessed or cracked
  • Phishing attacks
  • Password fatigue (too many to remember)
  • Often written down or reused

⚠️ Security Best Practices

  • Minimum 12 characters for passwords, 20+ for passphrases
  • Never reuse passwords across systems
  • Use a password manager
  • Enable password complexity requirements
  • Implement account lockout after failed attempts

Multi-Factor Authentication (MFA)

🛡️

🔐 What is MFA?

Multi-Factor Authentication requires users to provide two or more different types of authentication factors to prove their identity.

AUTHENTICATION FACTORS:
[1] Something you KNOW → Password
[2] Something you HAVE → Phone with SMS code
[3] Something you ARE → Fingerprint

MFA = At least 2 factors from DIFFERENT categories

📱 Common MFA Methods

  • SMS/Text codes – One-time password sent to phone
  • Authenticator apps – Google Authenticator, Microsoft Authenticator
  • Email verification – Code sent to registered email
  • Hardware tokens – YubiKey, RSA SecurID
  • Biometric + PIN – Fingerprint then PIN
  • Push notifications – Approve login on trusted device

🎯 2FA vs MFA

2FA (Two-Factor Authentication) – Exactly 2 factors

Example: Password + SMS code

MFA (Multi-Factor Authentication) – 2 or more factors

Example: Password + SMS + Fingerprint

✅ Benefits

  • Dramatically increases security
  • Protects against stolen passwords
  • Reduces phishing success rate
  • Provides audit trail
  • Required by many compliance standards

❌ Drawbacks

  • More complex for users
  • Requires additional device/token
  • Can be inconvenient
  • SMS vulnerable to SIM swapping
  • Recovery can be difficult if factor lost

🏆 Industry Standard

MFA is now considered essential for any system handling sensitive data. NIST, GDPR, and PCI-DSS all recommend or require MFA.

Biometric Authentication

👆

🧬 What is Biometric Authentication?

Using unique physical or behavioural characteristics to verify identity. Unlike identification, authentication compares the biometric data against a stored template to confirm it's really you.

BIOMETRIC AUTH PROCESS:
[1] ENROLMENT → Scan biometric, create template, store securely
[2] VERIFICATION → Scan biometric again
[3] COMPARISON → Compare scan to stored template
[4] DECISION → Match above threshold? GRANT : DENY

📊 Accuracy Metrics

  • FAR (False Accept Rate) – Wrong person accepted
  • FRR (False Reject Rate) – Correct person rejected
  • CER (Crossover Error Rate) – Balance point (lower is better)

Systems must balance security (low FAR) with usability (low FRR)

🎯 Most Common Methods

  • Fingerprint – Most widely deployed, mature technology
  • Face recognition – Increasingly popular in smartphones
  • Iris scanning – Very accurate, used in high-security
  • Voice authentication – Common in phone banking

✅ Benefits

  • Cannot be forgotten or lost
  • Difficult to fake (depending on method)
  • Convenient and fast
  • Non-transferable
  • User-friendly

❌ Drawbacks

  • Expensive hardware
  • Privacy concerns (data storage)
  • Cannot be changed if compromised
  • False positives/negatives
  • Can fail with injury/illness
  • Vulnerable to spoofing attacks

⚠️ Security Concerns

Biometrics can be spoofed using photos (face), fingerprint molds, or voice recordings. Always store biometric data as hashed templates, never raw images, and combine with other authentication factors!

Authorisation: What Can You Do?

🔑

🚪 Core Concept

Authorisation determines what an authenticated user is allowed to access and what actions they can perform.

After proving who you are (authentication), the system decides what you can do (authorisation).

USER: john.smith [AUTHENTICATED]
REQUESTING: /admin/database/delete
CHECKING PERMISSIONS...
ROLE: Standard_User
PERMISSION: READ_ONLY
RESULT: ACCESS_DENIED - Insufficient privileges

🔐 Key Principle: Least Privilege

Users should only have the minimum permissions necessary to perform their job. No more, no less.

🎭 Role-Based Access Control (RBAC)

Permissions assigned based on user's role in the organization

Example Roles:

  • Admin – Full system access
  • Manager – Department data access
  • Employee – Own data + shared resources
  • Guest – Read-only public data

📋 Access Control Lists (ACLs)

Specific permissions for individual users or groups on specific resources

Example ACL:

  • File: budget_2024.xlsx
  • john.smith: READ, WRITE
  • finance_team: READ
  • everyone: DENY

RBAC vs ACL Comparison

Feature Role-Based (RBAC) Access Control Lists (ACL)
Granularity Coarse-grained (role level) Fine-grained (per resource)
Management Easier to manage (assign roles) More complex (many ACL entries)
Scalability Scales well with users Can become unwieldy
Flexibility Less flexible (role-based only) Very flexible (per-user, per-resource)
Use Case Organizations with defined roles Systems needing specific exceptions
Example HR Manager can access HR database Jane can edit THIS specific document

✅ RBAC Benefits

  • Simple to understand and implement
  • Easy to onboard new users (assign role)
  • Reduces admin overhead
  • Aligns with organizational structure
  • Easier to audit

✅ ACL Benefits

  • Precise control over resources
  • Handle exceptions easily
  • Per-user customization
  • Temporary access grants
  • Detailed permission sets (read/write/execute)

🎯 Best Practice: Hybrid Approach

Many systems use RBAC as the foundation with ACLs for exceptions. Roles provide baseline permissions, ACLs handle special cases.

Accountability: Track Everything

📋

📊 Core Concept

Accountability ensures that every action within a system can be traced back to the responsible user.

It creates a permanent record of who did what, when, and where.

[2025-01-07 14:32:15] USER: john.smith | ACTION: LOGIN | IP: 192.168.1.100
[2025-01-07 14:33:22] USER: john.smith | ACTION: ACCESS_FILE | FILE: salary_data.xlsx
[2025-01-07 14:35:44] USER: john.smith | ACTION: MODIFY_FILE | FILE: salary_data.xlsx
[2025-01-07 14:38:19] USER: john.smith | ACTION: DELETE_FILE | FILE: temp_report.doc
[2025-01-07 14:42:05] USER: john.smith | ACTION: LOGOUT

📝 Audit Logs

Comprehensive records of system activities

Essential Elements:

  • Who – User identifier
  • What – Action performed
  • When – Timestamp (precise)
  • Where – Source IP, location, device
  • Result – Success or failure

📊 User Activity Monitoring

Real-time tracking of user actions

Tracked Activities:

  • Login/logout events
  • File access and modifications
  • Database queries
  • Configuration changes
  • Failed access attempts
  • Privilege escalation

✅ Benefits

  • Deters malicious activity
  • Enables incident investigation
  • Supports compliance (GDPR, SOX, HIPAA)
  • Identifies security breaches
  • Provides evidence for legal cases
  • Improves system understanding

❌ Drawbacks

  • Storage costs for massive logs
  • Performance impact on systems
  • Privacy concerns for users
  • Requires secure log storage
  • Log analysis can be overwhelming
  • Retention policies needed

🔐 Securing Audit Logs

Logs themselves must be protected! Use:

  • Write-only access – Users cannot delete their own logs
  • Encryption – Protect sensitive logged data
  • Offsite backup – Prevent tampering or loss
  • Integrity checks – Detect log manipulation

Exam-Style Questions

📋 Scenario

You are a security consultant advising SecureHealth Ltd, a healthcare technology company that develops patient management software used by GP surgeries and hospitals.

Their current system has basic username/password authentication, but they've experienced several security incidents:

  • Unauthorised access to patient records after a doctor's password was phished
  • Unable to identify which staff member deleted critical medical notes
  • A receptionist accidentally accessed consultant-only financial reports
  • No audit trail when data breaches are investigated

SecureHealth must comply with GDPR and NHS Data Security Standards. They have a budget of £50,000 for security improvements and 6 months to implement changes.

The following questions relate to this scenario.

📝 Section A – Short Response Questions

Question 1 – 2 marks (State)

State two elements of the IAAA model that SecureHealth's current system is failing to implement properly.

Question 2 – 3 marks (Explain)

Explain how implementing multi-factor authentication (MFA) would have prevented the phishing incident where the doctor's password was compromised.

Your answer should include what MFA is and why it provides better security than passwords alone.

Question 3 – 4 marks (Describe)

Describe how Role-Based Access Control (RBAC) could prevent the receptionist from accessing consultant-only financial reports.

Include how roles would be defined and how permissions would be assigned.

📝 Section B – Extended Response Questions

Question 4 – 5 marks (Compare)

SecureHealth is considering three authentication methods for their new system:

  • Option A: Passwords + SMS codes (2FA)
  • Option B: Passwords + Authenticator app + Fingerprint (MFA)
  • Option C: Smart cards + PIN

Compare these options in terms of:

  • Security level
  • User convenience
  • Implementation cost

Include at least two differences in your answer.

Question 5 – 8 marks (Discuss)

Discuss how implementing audit logs and user activity monitoring would help SecureHealth identify who deleted the critical medical notes and prevent future incidents.

In your response, you should:

  • Explain what information audit logs should capture
  • Describe how this supports accountability
  • Discuss how audit logs help with GDPR compliance
  • Use specific examples from the scenario (e.g., tracking who accessed patient records, monitoring deletion events)

📝 Section C – Evaluation Question

Question 6 – 12 marks (Evaluate)

SecureHealth must implement a comprehensive IAAA security model. They are considering two approaches:

Option A: Phased Implementation

  • Phase 1 (2 months): Implement MFA and basic audit logging
  • Phase 2 (2 months): Deploy RBAC system with defined roles
  • Phase 3 (2 months): Add biometric authentication and advanced monitoring
  • Total cost: £45,000

Option B: Complete Implementation

  • All-at-once (6 months): Implement full IAAA model with MFA, biometrics, RBAC, ACLs, and comprehensive audit system
  • More complex deployment requiring system downtime
  • Total cost: £55,000 (over budget by £5,000)

Evaluate which approach would be most suitable for SecureHealth.

You should:

  • Consider the benefits and limitations of each approach
  • Evaluate which security priorities should be addressed first
  • Reference the specific incidents mentioned in the scenario
  • Consider budget constraints, compliance requirements (GDPR/NHS), and patient safety
  • Discuss the risks of phased vs immediate implementation
  • Provide a final justified conclusion and recommendation
