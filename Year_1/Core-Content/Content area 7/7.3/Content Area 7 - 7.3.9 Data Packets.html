What Are Data Packets?

Definition

A data packet is a small unit of data that is transmitted across a network. Large amounts of data are broken down into smaller packets for transmission, then reassembled at the destination.

Why Use Packets?

  • Efficient use of bandwidth: Multiple users can share the same network connection by interleaving packets
  • Error handling: If one packet is corrupted, only that packet needs to be retransmitted (not the entire file)
  • Multiple paths: Packets can take different routes to the destination, avoiding congestion
  • Fair sharing: No single transmission monopolizes the network - packets from different sources alternate
  • Reliability: Packets can be checked for errors and acknowledged individually

Analogy

Think of sending a book through the mail. Instead of sending the entire book as one heavy package (which could get lost), you send each page in a separate envelope with:

  • Sender's address (source IP)
  • Recipient's address (destination IP)
  • Page number (sequence number)
  • The actual page content (payload/data)

The recipient receives the pages, checks they're all there, sorts them by page number, and reconstructs the book. If a page is missing, they can request just that page be resent.

Packet Structure

Every packet consists of three main parts:

Header

Contains:

• Source IP address
• Destination IP address
• Protocol type
• Sequence number
• Packet length
• Time to Live (TTL)

Payload (Data)

Contains:

The actual data being transmitted

• Could be part of a web page, email, file, video stream, etc.

• Typically 500-1500 bytes

Trailer (Footer)

Contains:

• Checksum/CRC for error detection
• End-of-packet marker
• Error checking data

Header Fields Explained

Source & Destination IP

Identifies where the packet came from and where it's going

Example: 192.168.1.100 → 93.184.216.34

Sequence Number

Orders packets so they can be reassembled correctly at destination

Example: Packet 1 of 150

Time to Live (TTL)

Maximum number of hops (routers) the packet can pass through before being discarded

Purpose: Prevents packets from circulating forever

Protocol Type

Indicates which protocol is being used (TCP, UDP, ICMP, etc.)

Example: Protocol 6 = TCP

Packet Switching vs Circuit Switching

Feature Circuit Switching Packet Switching
Connection Type Dedicated physical path established No dedicated path - packets route independently
Setup Connection must be established before transmission No setup required - packets sent immediately
Resource Usage Resources reserved for entire duration (even if idle) Resources shared - only used when packets are transmitted
Bandwidth Efficiency Inefficient - wasted during silence/idle periods Efficient - bandwidth shared among multiple users
Packet Order Data arrives in order (same path) Packets may arrive out of order (different paths)
Reliability Very reliable - dedicated connection Less reliable - packets can be lost or delayed
Latency Low, consistent latency once connected Variable latency depending on congestion
Example Use Traditional telephone networks Internet, email, web browsing, VoIP
Cost Expensive - dedicated resources Cost-effective - shared infrastructure
Fault Tolerance If connection fails, call drops completely Packets can reroute around failures automatically

💡 Modern Networks: The internet uses packet switching because it's more efficient for bursty, unpredictable data traffic. Circuit switching is better for continuous, real-time communications but wastes bandwidth during idle periods.

How Packets Are Routed

The Routing Process

When you send data across the internet, it doesn't travel directly to the destination. Instead, packets "hop" through multiple routers, each making independent decisions about the best next hop.

Step-by-Step Journey

1️⃣

Packetization

Data is broken into packets with headers containing source and destination IP addresses

2️⃣

First Hop

Packet sent to default gateway (home router), which examines destination IP

3️⃣

Router Decision

Each router checks routing table to determine best next hop toward destination

4️⃣

Multiple Hops

Packet passes through 10-20 routers (hops), each decreasing TTL by 1

5️⃣

Arrival

Packet reaches destination network and is delivered to target device

6️⃣

Reassembly

All packets are collected, reordered by sequence number, and reassembled into original data

Routing Decisions

Routers make decisions based on:

  • Routing tables: Lists of network destinations and which interface to forward packets to
  • Metrics: Cost, hop count, bandwidth, congestion levels
  • Dynamic updates: Routing protocols (BGP, OSPF, RIP) share network topology information
  • Load balancing: Distributing traffic across multiple paths for efficiency

TCP vs UDP Protocols

Two main transport layer protocols handle packets differently:

Feature TCP (Transmission Control Protocol) UDP (User Datagram Protocol)
Connection Type Connection-oriented (3-way handshake) Connectionless (no handshake)
Reliability Guaranteed delivery - retransmits lost packets No guarantee - packets may be lost
Ordering Packets delivered in correct order No ordering - may arrive out of sequence
Error Checking Extensive error checking and acknowledgments Basic checksum only
Speed Slower due to acknowledgments and retransmissions Faster - no overhead for reliability
Header Size 20-60 bytes (larger) 8 bytes (smaller)
Flow Control Yes - prevents overwhelming receiver No flow control
Congestion Control Yes - slows down when network congested No congestion control
Use Cases Web browsing (HTTP/HTTPS), email (SMTP), file transfer (FTP), SSH Video streaming, online gaming, VoIP, DNS queries, live broadcasts
When to Use When data integrity is critical and latency is acceptable When speed matters more than reliability or occasional data loss is acceptable

Real-World Examples

TCP: Downloading a file - you need every byte to be correct and in order. A corrupted file is useless.

UDP: Video call - if a few packets are lost, you might see brief pixelation, but the conversation continues. Waiting for retransmission would cause worse disruption than losing the data.

TCP Three-Way Handshake

What is the Three-Way Handshake?

Before TCP can transmit data, it establishes a connection using a three-step process. This ensures both parties are ready to communicate and agree on initial parameters.

The Three Steps

1️⃣

SYN (Synchronize)

Client → Server

"Hello, I want to establish a connection. My initial sequence number is X."

Client sends SYN packet with initial sequence number

2️⃣

SYN-ACK

Server → Client

"I acknowledge your request. My sequence number is Y. I'm ready!"

Server responds with SYN-ACK packet

3️⃣

ACK (Acknowledge)

Client → Server

"I acknowledge your acknowledgment. Connection established!"

Client sends final ACK, connection is now open

After the Handshake

  • Data transmission begins: Both parties can now send and receive data
  • Acknowledgments continue: Each data packet is acknowledged to confirm receipt
  • Sequence numbers track data: Ensures packets are reassembled in correct order
  • Connection termination: Uses FIN-ACK process to close connection gracefully

⚠️ Overhead Trade-off

The three-way handshake adds latency (round-trip delay) before any data is transmitted. This is why TCP is slower to start than UDP, but provides guaranteed reliability once established.

Encapsulation & De-encapsulation

What is Encapsulation?

Encapsulation is the process of adding headers (and trailers) to data as it passes down through the OSI model layers. Each layer adds its own header containing protocol-specific information.

The Encapsulation Process (Sending Data)

Layer 7-5: Application Data

Data: HTTP request, email, file content

User data is created by application

Layer 4: Transport

Adds: TCP/UDP header with port numbers

Result: Segment (TCP) or Datagram (UDP)

Layer 3: Network

Adds: IP header with source/destination IP addresses

Result: Packet

Layer 2: Data Link

Adds: Ethernet header/trailer with MAC addresses

Result: Frame

Layer 1: Physical

Converts to: Electrical signals, light pulses, or radio waves

Result: Bits transmitted over cable/fiber/air

De-encapsulation (Receiving Data)

The receiving device performs the reverse process:

  • Layer 1: Receives bits and converts to frame
  • Layer 2: Removes Ethernet header/trailer, checks destination MAC address
  • Layer 3: Removes IP header, checks destination IP address
  • Layer 4: Removes TCP/UDP header, checks port number, reassembles segments
  • Layer 7-5: Delivers data to correct application

Analogy

Think of encapsulation like preparing a package for shipping:

  • Your letter = Application data
  • Put in envelope with addresses = IP header added
  • Place in shipping box with tracking = TCP header added
  • Shipping company labels = Ethernet frame added
  • Physical transport = Bits transmitted

MTU and Packet Fragmentation

Maximum Transmission Unit (MTU)

The MTU is the largest packet size (in bytes) that can be transmitted over a network link. If a packet exceeds the MTU, it must be fragmented into smaller packets.

Common MTU Values

Ethernet

MTU: 1500 bytes

Most common for wired LANs and the internet

Wi-Fi

MTU: 1500 bytes (typically)

Can be lower depending on configuration

PPPoE (DSL)

MTU: 1492 bytes

8 bytes smaller due to PPPoE header overhead

Jumbo Frames

MTU: 9000 bytes

Used in data centers for high-performance networks

Packet Fragmentation

When Does Fragmentation Occur?

When a packet is larger than the MTU of the next network segment, the router fragments it into smaller pieces that fit within the MTU.

Fragmentation Process

  • Original packet: 3000 bytes (exceeds 1500 byte MTU)
  • Fragment 1: 1500 bytes with header flag "More Fragments" = Yes
  • Fragment 2: 1500 bytes with "More Fragments" = Yes
  • Fragment 3: Remaining bytes with "More Fragments" = No (last fragment)
  • Each fragment: Contains offset information to indicate its position in original packet

Problems with Fragmentation

  • Performance overhead: Fragmenting and reassembling packets requires CPU processing
  • Increased packet loss risk: If any fragment is lost, the entire original packet must be retransmitted
  • Router burden: Routers must perform fragmentation, slowing down packet forwarding
  • Reassembly timeout: If fragments arrive too slowly, the receiving device may discard incomplete packets

💡 Solution: Modern networks use Path MTU Discovery (PMTUD) to determine the smallest MTU along the entire path and send packets that size from the start, avoiding fragmentation.

Packet Loss, Latency, and Jitter

Packet Loss

What is Packet Loss?

Packet loss occurs when one or more packets fail to reach their destination. This can happen for various reasons and impacts application performance differently depending on the protocol.

Causes of Packet Loss

  • Network congestion: Routers/switches drop packets when buffers overflow
  • Hardware failures: Faulty cables, NICs, or switches causing transmission errors
  • Wireless interference: Signal degradation in Wi-Fi causing dropped packets
  • Routing errors: Packets sent to wrong destination or looping endlessly (TTL expires)
  • Firewall filtering: Security devices blocking certain packets intentionally

Impact

TCP: Automatically retransmits lost packets, but causes delays. UDP: Lost packets are gone forever - causes glitches in video/audio streams or gaming.

Latency

What is Latency?

Latency (or ping) is the time it takes for a packet to travel from source to destination. Measured in milliseconds (ms).

Sources of Latency

  • Propagation delay: Time for signal to physically travel through cables (speed of light limitation)
  • Transmission delay: Time to push all packet bits onto the wire (depends on bandwidth)
  • Processing delay: Time for routers to examine headers and make forwarding decisions
  • Queuing delay: Time spent waiting in router buffers during congestion
  • Distance: Longer physical distance = higher latency (e.g., UK to Australia = ~300ms)

Acceptable Latency

  • Web browsing: 100-200ms acceptable
  • Video streaming: Can tolerate 200-500ms with buffering
  • VoIP/Video calls: <150ms ideal, >300ms causes noticeable delays
  • Online gaming: <50ms ideal, >100ms causes "lag"

Jitter

What is Jitter?

Jitter is the variation in packet arrival times. Packets taking different routes or experiencing variable congestion arrive at inconsistent intervals.

Impact

  • Voice/video calls: Audio stutters, video freezes, or choppy playback
  • Real-time applications: Unpredictable performance, difficult to synchronize
  • Gaming: Inconsistent responsiveness, "rubber-banding" movement

Solution: Jitter Buffers

Real-time applications use jitter buffers to temporarily store incoming packets and release them at consistent intervals, smoothing out timing variations. This adds slight latency but improves quality.

Quality of Service (QoS)

What is QoS?

Quality of Service (QoS) is a set of techniques used to manage network traffic and prioritize certain types of packets over others. This ensures critical applications get the bandwidth and low latency they need.

Why QoS is Needed

Without QoS, all traffic is treated equally. This causes problems when:

  • Bandwidth is limited: Heavy downloads can starve video calls of bandwidth
  • Latency-sensitive apps: VoIP packets delayed behind large file transfers
  • Business priorities: Critical business apps compete with recreational traffic
  • Congestion: Network becomes saturated, all traffic suffers equally

QoS Techniques

Traffic Classification

Identify and mark packets based on:

• Application type (VoIP, video, web)
• Port numbers
• IP addresses
• DSCP (DiffServ) markings

Priority Queuing

Separate traffic into different queues with priority levels:

• High: VoIP, real-time video
• Medium: Business applications
• Low: Downloads, bulk transfers

Bandwidth Allocation

Reserve guaranteed bandwidth for important traffic:

• VoIP: 20% minimum
• Video conferencing: 30%
• Remaining: Shared fairly

Traffic Shaping

Control rate of traffic transmission:

• Smooth bursty traffic
• Prevent congestion
• Enforce bandwidth limits

QoS Priority Example

Priority Level Traffic Type Characteristics Treatment
Highest VoIP, Video Conferencing Low latency requirement, constant bandwidth Process immediately, reserved bandwidth
High Business-critical apps, Database transactions Important to business operations High priority, guaranteed bandwidth
Medium Email, Web browsing, Standard applications Normal user traffic, some delay acceptable Fair sharing, best effort
Low File downloads, Software updates, Backups Bulk transfers, delay tolerant Use remaining bandwidth, can be throttled

Module Summary - Data Packets

Key Takeaways

  • Data packets: Small units of data that are transmitted independently across networks
  • Packet structure: Header (routing info), Payload (actual data), Trailer (error checking)
  • Packet switching: Efficient, fault-tolerant method where packets take independent paths
  • TCP vs UDP: TCP provides reliability and ordering; UDP provides speed for real-time apps
  • Encapsulation: Each OSI layer adds its own header as data moves down the stack
  • MTU & fragmentation: Packets larger than MTU must be fragmented, causing overhead
  • Packet loss: Dropped packets due to congestion, errors, or hardware failures
  • Latency: Delay in packet transmission - critical for real-time applications
  • Jitter: Variation in packet arrival times - smoothed using jitter buffers
  • QoS: Traffic prioritization ensures critical applications get required bandwidth and low latency

Practical Understanding

Understanding data packets is fundamental to:

  • Troubleshooting network performance issues
  • Choosing appropriate protocols for applications
  • Designing QoS policies for business networks
  • Optimizing network configurations for specific use cases
  • Understanding how the internet actually works at a technical level
