What is Client-Server Architecture?

  • A client-server model is a distributed computing architecture where tasks are divided between service providers (servers) and service requesters (clients)
  • Client: A device or application that requests services or resources from a server
  • Server: A powerful computer or application that provides services, resources, or data to clients
  • Clients and servers communicate over a network using defined protocols
  • This model forms the foundation of most modern networked applications and the Internet

How Client-Server Communication Works

The Request-Response Cycle

  1. Client sends a request: The client initiates communication by sending a request to the server for a specific service or resource
  2. Server processes the request: The server receives the request, processes it, and accesses necessary resources (database, files, etc.)
  3. Server sends a response: The server sends back the requested data or confirmation to the client
  4. Client receives and displays: The client receives the response and presents it to the user

Real-World Example: Web Browsing

1. You type a URL in your browser (client)

2. Browser sends HTTP request to web server

3. Server retrieves the webpage files

4. Server sends HTML, CSS, JS back to browser

5. Browser displays the webpage

Advantages of Client-Server Model

  • Centralized data management: All data is stored in one location, making it easier to manage, backup, and secure
  • Improved security: Servers can implement robust security measures, access controls, and authentication
  • Resource sharing: Multiple clients can access the same resources simultaneously (printers, databases, files)
  • Scalability: Easy to add more clients without major infrastructure changes
  • Centralised updates: Software and data updates only need to be applied on the server
  • Better performance: Powerful servers can handle complex processing tasks efficiently
  • Reduced data duplication: Single source of truth for data across the organisation
5 / 15

Disadvantages of Client-Server Model

  • Single point of failure: If the server goes down, all clients lose access to services
  • High initial cost: Servers are expensive to purchase and maintain
  • Network dependency: Requires a reliable network connection; poor network affects all users
  • Server maintenance: Requires skilled IT staff to manage and maintain servers
  • Scalability limits: Server can become overloaded if too many clients connect simultaneously
  • Complexity: More complex to set up and configure than peer-to-peer networks
  • Network congestion: Heavy traffic can slow down the entire network

Two-Tier Client-Server Architecture

Overview

The client communicates directly with the database server. The client contains the presentation layer and business logic, while the server manages data.

✓ Advantages

  • Simple architecture
  • Fast communication
  • Easy to maintain
  • Lower cost

✗ Disadvantages

  • Less secure
  • Poor scalability
  • Client must be powerful
  • Database exposed to clients
7 / 15

Three-Tier Client-Server Architecture

Overview

Introduces a middle tier (application server) between client and database. The client handles presentation, application server handles business logic, and database server manages data.

✓ Advantages

  • Better security (database isolated)
  • Excellent scalability
  • Easier to maintain and update
  • Clients can be lightweight
  • Reusable business logic

✗ Disadvantages

  • More complex to design
  • Higher cost (additional servers)
  • Slower than two-tier
  • Requires more expertise
8 / 15

N-Tier Architecture

Overview

Extends beyond three tiers to include additional specialized layers such as caching servers, load balancers, API gateways, and microservices. Common in large-scale enterprise applications.

Common Additional Tiers

  • Load Balancer: Distributes incoming requests across multiple servers
  • Web Server Tier: Handles HTTP requests and serves static content
  • API Gateway: Manages and routes API requests
  • Cache Tier: Stores frequently accessed data for faster retrieval
  • Message Queue: Handles asynchronous communication between services
  • Search Tier: Dedicated servers for search functionality

Example: Netflix Architecture

Netflix uses an N-tier architecture with presentation (web/mobile apps), API gateway, microservices (recommendations, user profiles, payments), caching layers, and distributed databases across multiple data centres.

Thin Client vs Thick Client

Thin Client

Definition: Minimal processing on client; most work done on server

  • Characteristics: Lightweight, browser-based, minimal local storage
  • Examples: Web applications, Google Docs, cloud-based email
  • Advantages: Low maintenance, easy updates, works on any device
  • Disadvantages: Requires constant network, limited offline functionality

Thick Client

Definition: Significant processing on client; server for data storage

  • Characteristics: Desktop applications, local processing, rich features
  • Examples: Microsoft Office, Adobe Photoshop, video games
  • Advantages: Better performance, offline capability, rich UI
  • Disadvantages: Installation required, harder to update, platform-specific

Real-World Client-Server Applications

Email Systems

Clients: Outlook, Gmail app, Thunderbird
Servers: Mail servers (SMTP, POP3, IMAP)
Architecture: Three-tier with email client, mail server, and database

Web Applications

Clients: Web browsers (Chrome, Firefox, Safari)
Servers: Web servers (Apache, Nginx), application servers
Architecture: N-tier with load balancers, caching, CDNs

Online Banking

Clients: Banking apps, ATMs, web portals
Servers: Transaction servers, database servers, authentication servers
Architecture: Highly secure multi-tier with encryption and redundancy

Client-Server vs Peer-to-Peer

Client-Server

  • Centralised control and management
  • Better security and access control
  • Easier to back up and maintain
  • Requires dedicated server hardware
  • Single point of failure
  • Higher initial cost
  • Professional administration needed

Peer-to-Peer (P2P)

  • Decentralised - all devices equal
  • Lower cost (no dedicated server)
  • No single point of failure
  • Harder to manage and secure
  • Difficult to back up
  • Poor scalability
  • Best for small networks (under 10 devices)
